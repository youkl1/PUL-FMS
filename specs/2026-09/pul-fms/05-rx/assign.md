## 一、背景与问题（Problem）

### 背景

系统已实现「码进药出」全链路（采购 → 库房 → 药房 → 发药），但院内无码药品（中药饮片、院内制剂、供应商未赋码品种）没有追溯码，发药环节无法扫码，追溯链在此断裂；医保发〔2025〕7 号要求「先扫码后结算」，无码药品的处方在结算环节被拦。

三条硬约束（已拍板，不变）：**码必须扫 / 药必须发得出 / 账必须对得上**。冲突时「药必须发得出」优先，码的账事后补平，异常全程留痕。

药→码绑定三时点：

| 时点 | 机制 | 场景 |
|------|------|------|
| T1 事前 | 在架批量赋码 / 预贴码 | 预设药柜顺序（FEFO + 货位预指定码） |
| T2 事中 | 调剂时扫码绑定 | 边扫边拿 / 抓药扫码 / 病房摆药扫码 |
| T3 事后 | 先发药，手动补绑 + 异常台账 | 住院无扫码条件、扫码失败降级 |

### 用户痛点

> **痛点 1：无码药追溯断链** —— 无码药品发药无任何扫码记录，出问题无法溯源到批次。
>
> **痛点 2：医保结算被拦** —— 无码不支付，收费处只能退费改方，患者往返窗口。
>
> **痛点 3：豁免边界靠人脑** —— 哪些拆零药属于医保豁免，药师只能凭记忆判断，口径不一。
>
> **痛点 4：扫码失败卡流程** —— 门诊扫不出 / 码不符 / 住院摆药无扫码条件时，发药流程被卡死；药必须发得出，不能因码的问题拦住患者用药。

## 二、用户故事（User Stories）

### 用户故事 1（P1）：发药时无码药即时赋码

作为发药药师，在门诊发药遇到无码药品时，我希望能现场生成院内码、打印粘贴并完成扫码发药，以便处方正常结算、追溯不断链。

**独立验收：** 只做本故事，一张含无码药的处方即可完整走完「赋码 → 贴码 → 扫码发药 → 结算」。

**验收标准：**
- Given 处方行药品在标识码字典中无码，When 药师在发药页点击「赋码」，Then 系统生成 20 位院内码并弹出码签打印预览。
- WHEN 院内码已粘贴并扫码核对，THE SYSTEM SHALL 将码与处方绑定并写入台账，且 SHALL NOT 允许同一码绑定第二张处方。
- IF 药品被标记为「拆零豁免」，THEN THE SYSTEM SHALL 不触发赋码，直接按拆零流程发放。

### 用户故事 2（P2）：在架无码药批量赋码

作为药房管理员，在发药高峰前，我希望对药房在架的无码药品批量生成并打印码签，以便高峰发药不卡在赋码环节。

**独立验收：** 只做本故事，在架无码药可批量生成码签并贴码上架，发药时直接扫已贴码。

**验收标准：**
- Given 在架药品清单中存在无码药，When 管理员勾选药品并设置每种数量，Then 系统批量生成院内码并汇成打印任务。
- WHEN 某药品赋码数量超过其在架数量，THE SYSTEM SHALL 拦截并提示在架余量。

### 用户故事 3（P3）：赋码记录可追溯

作为质控管理员，在核查药品流向时，我希望赋码记录进入统一台账查询，以便院内码与厂商码同口径追溯。

**独立验收：** 只做本故事，追溯码查询页可查到院内赋码的码及其绑定处方。

**验收标准：**
- Given 一条院内赋码记录，When 在追溯码查询页输入该码，Then 展示码来源（院内赋码）、绑定处方号、操作人与时间。

### 用户故事 4（P1）：扫码失败手动补绑不卡流程

作为发药药师，在门诊扫码失败（扫不出 / 码不符 / 实物无码）或住院摆药无扫码条件时，我希望先从系统推荐的候选码中人工选定补绑，以便药先发得出、处方正常结算，码的账当场或事后补平。

**独立验收：** 只做本故事，一张含扫码失败行的处方可走手动补绑完成发药，补绑记录写入异常台账待复核。

**验收标准：**
- Given 处方行扫码失败，When 药师点击行内「手动补绑」，Then 系统按规则推荐候选码清单（药柜药品 = 货位序 → FEFO → 入库先后；非药柜药品 = 入库先后 FIFO），人工勾选确认后绑定成功、处方正常完成结算。
- WHEN 手动补绑完成，THE SYSTEM SHALL 给绑定记录打核验标记（bindType=manual，verified=待复核），且 SHALL NOT 重复扣减库存（数量账在发药锁数量时已扣，补绑只动码的归属）。
- IF 同一处方部分行扫码、部分行手动补绑，THEN THE SYSTEM SHALL 支持行级独立闭环、混合绑定。

### 用户故事 5（P2）：赋码异常台账日结复核

作为药房管理员 / 院区管理员，我希望补绑与住院后置异常集中进台账、当日班后逐条复核，以便码账与实物账日清日结、超时事项有人兜底。

**独立验收：** 只做本故事，补绑产生的台账记录当日可执行确认 / 改绑 / 关闭，超 24h 未确认自动升级提醒院区管理员。

**验收标准：**
- Given 门诊手动补绑完成，When 写入台账，Then 记录状态为「待复核」；Given 住院摆药完成未补绑，Then 自动生成「待补绑」记录驱动日结前补绑。
- WHEN 复核人执行「确认」，THE SYSTEM SHALL 将绑定记录核验标记转为「已复核」；执行「改绑」时 SHALL 释放错绑码回架、绑定正确码并记录旧码；执行「关闭」时 SHALL 仅在药已退等无需补绑情形下可用、码池不动。
- IF 台账记录超 24h 未确认，THEN THE SYSTEM SHALL 自动升级提醒院区管理员。

## 三、方案概述（Solution）

> **核心功能一句话描述** —— T1 事前批量赋码 / T2 事中扫码 / T3 事后手动补绑三时点全覆盖，让每一盒发出的药都有码可扫、可结算、可追溯，异常进台账日结闭环。

### 流程图（按信号触发：多角色 + 状态流转）

![处方赋码业务流程](../assets/rx-code-assign-flow.svg)

| 流程节点 | 页面/角色 | 用户行为 | 分支条件 | 异常去向 |
|---------|----------|---------|---------|---------|
| 处方下达 | HIS | 医生开方 | 含无码药才进入造码流程 | 有码 → 方案 b 常规发药 |
| 拉取处方·逐行验码 | 系统 | 拉取处方对照标识码字典 | 药品有码？ | 字典缺失 → 进异常码维护 |
| 生成院内赋码 | 系统 | 20 位=7 位标识码+9 位批次+4 位流水 | 拆零豁免药不赋码 | 流水冲突 → 重取号 |
| 码绑处方·写台账 | 系统 | 码状态=已赋码，写追溯台账 | — | 处方已退 → 赋码作废 |
| 批量赋码（提前贴码） | 发药药师 | 选在架无码药批量生成码签 | 赋码数 ≤ 在架数 | 超量拦截 |
| 打印码签·粘贴·扫码发药 | 发药药师 | 打印、粘贴、扫码双核对 | — | 打印失败 → 重打原码 |
| 扫码失败降级（T2→T3） | 发药药师 | 扫不出 / 码不符 / 住院无扫码条件 → 行内「手动补绑」 | 补绑候选有码？ | 在架无码 → 转 4.1 造码 |
| 手动补绑 | 发药药师 | 系统推荐候选码（药柜=货位序→FEFO；非药柜=FIFO），人工勾选确认 | 勾选数 ≤ 剩余应发数 | 绑错 → 台账改绑 |
| 异常台账日结 | 药房管理员 | 当日班后逐条复核：确认 / 改绑 / 关闭 | 超 24h 未确认 → 升级院区管理员 | 药已退 → 关闭留痕 |
| 扫码结算 | 医保 | 码随处方上传 | 拆零豁免直接结算 | 无码 → 不支付 |

### 升级点清单

- 4.1 新增处方即时赋码（发药环节触发）

## 四、功能需求（Feature Requirements）

### 4.1 新增处方即时赋码

**功能说明：** 发药药师在处方发药页对无码药品一键生成院内码、打印码签并扫码绑定，不发新页面，挂在既有处方发药页（disp）。拆零豁免药品不触发赋码。

**独立验收：** 只做本升级点，含无码药的处方可完整走完赋码 → 贴码 → 扫码发药 → 结算。

1. 列表（处方发药页明细行）
   1. 行状态标签（新增）：无码（橙）/ 豁免（灰）/ 已赋码（绿）；有码药品不显示标签
2. 按钮
   1. 赋码（新增）：无码药品行内显示；点击弹出赋码弹窗；处方已退时禁用，悬浮提示「处方已退」
3. 表单内容（赋码弹窗）
   1. 药品信息
      1. 药品名称
         1. 格式：文本框（自动带入不可手动修改）
         2. 提示内容：处方行自动带入
         3. 必填项
         4. 限制：无
      2. 批次
         1. 格式：下拉选择框
         2. 提示内容：请选择批次
         3. 必填项
         4. 选择项：该药在架批次，默认 FEFO 最近效期批次
      3. 有效期至
         1. 格式：日期选择框
         2. 提示内容：请选择有效期
         3. 必填项
         4. 限制：不得早于当前日期；≤180 天黄字预警；随批次自动带入可改
      4. 赋码数量
         1. 格式：数字输入框
         2. 提示内容：请输入赋码数量
         3. 必填项
         4. 限制：正整数，默认=处方行数量，不得大于该批次在架数量，超出红字拦截
      5. 院内码
         1. 格式：文本框（自动生成不可手动修改）
         2. 提示内容：确认生成后自动展示
         3. 必填项
         4. 限制：20 位=7 位标识码+9 位批次+4 位流水；[假设]标识码段 9 开头区隔厂商码
4. 表单按钮
   1. 取消：关闭弹窗，不生成码
   2. 确认生成：
      1. 前端：必填与数量校验，失败 toast 精确文案（如「赋码数量不能大于在架数量 X」）；成功后生成院内码并进入打印预览
      2. 后端：在架数量复核；生成院内码（流水号互斥）；码状态=已赋码
   3. 打印（生成成功后进入打印预览）：
      1. 前端：调系统打印；失败 toast「打印失败，可重打原码」，重打不生成新码
      2. 打印份数：选填，整数，默认 1，上限 5
   4. 扫码绑定（打印粘贴后）：
      1. 前端：扫已贴码与弹窗码比对，一致则行标签变绿「已赋码」；不一致红字「码与药品不符」
      2. 后端：码与处方绑定（一处方一码），同一码绑定第二张处方时硬拦截

### 4.2 新增在架药品批量赋码

**功能说明：** 药房管理员对当前药房在架无码药品批量生成并打印码签，提前贴码上架，发药时直接扫已贴码。新页面，挂在出库管理 > 处方单批量赋码（assignBatch，菜单已占位）。

**独立验收：** 只做本升级点，在架无码药可批量赋码贴码，发药页扫码直接命中。

1. 搜索栏
   1. 药品名称：模糊搜索
   2. 批次：模糊搜索
   3. 赋码状态：下拉选（未赋码/部分赋码/已足量）
2. 按钮
   1. 批量生成（新增）：勾选药品后可用；生成中按钮 loading，禁止重复提交
   2. 打印全部（新增）：批量生成成功后可用，连续打印码签
3. 列表（按有效期升序，FEFO）
   1. 勾选框（新增）：仅无码药品行可勾选
   2. 药品名称 / 规格 / 批次：保留原有功能
   3. 在架数量：保留原有功能
   4. 已赋码数量（新增）：该药品该批次累计已赋码数，防重复赋码
   5. 赋码数量（新增）：行内数字输入，默认=在架余量，不得大于在架余量
   6. 赋码状态（新增）：未赋码（橙点）/ 部分赋码（黄点+数量比）/ 已足量（绿点）
4. 表单按钮
   1. 批量生成：
      1. 前端：勾选与数量校验，失败 toast 精确文案（如「唯可来：赋码数量超过在架余量 3」）；成功 toast「已生成 N 张码签」并进入打印任务
      2. 后端：逐药品复核在架余量；批量生成院内码（流水互斥）；码状态=已赋码
   2. 打印全部：
      1. 前端：连续调系统打印；单张失败记入失败清单，打印结束 toast「成功 X 张，失败 Y 张，可重打」

### 4.3 赋码记录接入台账追溯查询

**功能说明：** 院内赋码的码写入统一追溯台账，在既有「追溯码查询」页可查，与厂商码同口径展示来源与绑定处方。不新建页面，扩展现有追溯码查询（trace-q）。

**独立验收：** 只做本升级点，院内码可在追溯码查询页完整查出来源与生命周期。

1. 搜索栏
   1. 追溯码：精确搜索（保留原有功能，兼容 20 位院内码）
2. 列表（查询结果）
   1. 来源（优化）：新增枚举值「院内赋码」，与「采购入库」「其他入库」并列展示；扩展「手动补绑」标记 + 核验状态列
3. 详情
   1. 院内赋码徽标（新增）：详情头部蓝色徽标，与厂商码视觉区分
   2. 展示字段（新增）：绑定处方号、操作人、赋码时间、发药时间、结算状态
   3. 核验状态（新增）：扫码核验 / 人工补绑（待复核）/ 已复核，手动补绑记录高亮提示

### 4.4 新增手动补绑（T3）

**功能说明：** 有码未扫场景的兜底通道：门诊发药扫码失败（扫不出 / 码不符 / 实物无码）行内手动补绑，当下完成、结算时已有码，不碰医保「先扫码后结算」红线；住院摆药默认事后补绑。系统按规则推荐候选码、人工最终选定。补绑只动码的归属，**不重复扣库存**（数量账在发药锁数量时已扣），码账与实物账的最终校准器 = 盘点。

**独立验收：** 只做本升级点，含扫码失败行的处方可走补绑完成发药并入台账待复核；住院摆药单可事后补绑。

1. 入口
   1. disp 发药页：扫码失败行行内「手动补绑」按钮（新增）；行加异常标记
   2. tray 摆药页：行内「补绑码」按钮（新增）+ 摆药单「完成摆药 · 事后补绑」入口（新增）
   3. 混合绑定允许：同一处方部分行扫码、部分行手动补绑，行级独立闭环
2. 表单内容（补绑弹窗）
   1. 补绑原因
      1. 格式：下拉选择框
      2. 提示内容：请选择补绑原因
      3. 必填项
      4. 选择项：扫码失败 / 码不符 / 住院后置
   2. 候选码清单
      1. 格式：勾选列表（系统推荐序）
      2. 提示内容：系统按规则推荐，人工最终选定
      3. 必填项（至少勾选 1 个）
      4. 推荐规则：药柜药品 = 货位顺序 → FEFO 效期先出 → 同批按入库先后；非药柜药品 = 入库先后 FIFO
      5. 限制：勾选数量不得超过该行剩余应发数，超出红字拦截
   3. 空态：该药在架无可补绑码时，提示「在架无码」并引导走 4.1 即时赋码造码
3. 表单按钮
   1. 取消：关闭弹窗，不产生绑定
   2. 确认绑定：
      1. 前端：勾选数 ≤ 剩余应发数校验；成功 toast「已补绑 N 码，待班后复核」
      2. 后端：码与单据绑定；核验标记 bindType=manual、verified=待复核；写赋码异常台账（门诊=待复核记录；住院摆药完成未补绑先产生待补绑记录）

### 4.5 新增赋码异常台账（rx-exc）

**功能说明：** 补绑与后置异常的集中复核工作台，日结制闭环。新页面，挂出库管理 > 赋码异常台账（自主新增菜单，带「新」chip，客户菜单无此项需报备）。台账同时是补绑待办清单。

**独立验收：** 只做本升级点，补绑 / 住院后置异常可集中查询、逐条执行确认 / 改绑 / 关闭，超时升级提醒。

1. 搜索栏
   1. 异常单号 / 处方号 / 摆药单号：精确搜索
   2. 异常类型：下拉选（扫码失败 / 码不符 / 住院后置）
   3. 状态：下拉选（待补绑 / 待复核 / 已确认 / 已改绑 / 已关闭）
   4. 时间范围：日期区间，默认当日
2. 列表
   1. 字段清单：异常单号 / 异常类型 / 来源单据（处方号或摆药单号）/ 药品 + 批次 / 补绑码 / 补绑规则 / 操作人 / 时间 / 状态
   2. 超 24h 未确认记录高亮，并升级提醒院区管理员
3. 状态机：待补绑 → 待复核 → 已确认 / 已改绑 / 已关闭（三者为终态）
4. 记录产生时机
   1. 住院摆药完成未补绑 → 自动生成「待补绑」记录，驱动日结前补绑
   2. 门诊扫码失败手动补绑完成 → 产生「待复核」记录
5. 处理动作（三选一，行内按钮）
   1. 确认：账实相符，绑定记录 verified 转「已复核」，台账记录转「已确认」
   2. 改绑：释放错绑码回架、绑定正确码，记录旧码（oldCode），台账记录转「已改绑」
   3. 关闭：药已退等无需补绑情形，码池不动，台账记录转「已关闭」留痕

### 边界与异常

1. 拆零豁免药品：药品字典带豁免标记的不触发赋码，直接按拆零流程发放（splitQty 记消耗）。
2. 重复赋码：同一码绑定第二张处方时硬拦截。
3. 处方作废：赋码后 HIS 退方，已赋码自动作废并写台账（状态=已作废），码不复用。
4. 打印异常：打印失败可重打原码，禁止重新生成新码（防一药多码）。
5. 并发赋码：同一药品并发生成时流水号互斥，冲突自动重取。
6. 效期缺失：批次无效期数据时强制手填，不托底。
7. 补绑后退药：走既有 rx-ret / tray-ret 退药流程解绑回架，台账记录关闭留痕；退药发生在补绑前的，台账记录直接关闭、码池不动。
8. HIS 撤销处方分时点：未发药 = 释放锁定、已绑码解绑回架（码复用）；已发药 = 转退药流程。
9. 绑错批次 / 码双通道：异常台账「改绑」+ 盘点差异处理提示改绑（inv 模块加动作），账实差异最终由盘点校准。
10. 门诊补绑不碰医保红线：门诊手动补绑当下同步完成，结算时已有码，满足「先扫码后结算」；仅住院场景允许事后补绑。

### Non-Goals（本次明确不做）

- 不做码签打印机驱动层对接（走操作系统打印，型号适配见开放问题）。
- 不做供应商/院外环节的赋码（采购侧已有码单池）。
- 不做病区侧赋码（病区段按已拍板的两段式，码随发药单绑患者）。
- 不做豁免清单的自动判定（本期由药品字典人工维护标记）。
- 不做自动化补绑引擎（后续迭代，积累手动补绑数据后再评估命中率）。
- 不做医保冲正接口（已结算后退药的医保冲正走既有结算通道，不新增接口）。
- 不做病区 PDA 扫码（护理系统范畴）。

## 五、技术与数据需求

### 5.1 数据与业务逻辑
- 院内码写入追溯码台账（TRACE_CODE），来源字段 source=院内赋码；码状态机：已赋码 → 已发药（随处方）→ 已结算；作废为终态不可复活。
- 绑定记录新增核验维度：bindType（scan / manual）+ verified 三档（扫码核验 / 人工补绑-待复核 / 已复核）；**码状态机不变**，异常不新建码状态，避免状态机膨胀。
- 赋码数量不得超该批次在架数量；在架口径沿用现有库存推导（入库−出库−损耗−盘亏）。
- 补绑只动码的归属，不重复扣库存（数量账在发药锁数量时已扣）。
- 赋码异常台账（rx-exc）为独立记录表，字段见 4.5；日结制：当日班后复核，超 24h 未确认自动升级提醒院区管理员。
- 豁免标记挂在药品字典（DRUGS），发药验码与批量赋码清单共用此标记。
- [假设] 院内码 20 位编码沿用现有追溯码规则，标识码段以 9 开头区隔厂商码，避免与采购码碰撞。

### 5.2 接口诉求（PM 业务层）
- 新增：院内码生成接口（入：药品+批次+数量；出：码清单），要求批量 100 张内秒级返回。
- 新增：码-处方绑定/解绑接口（随发药、退方联动），绑定请求带 bindType / 补绑原因。
- 新增：补绑候选码推荐接口（入：药品+数量+场景；出：按规则排序的候选码清单）。
- 新增：异常台账查询与处理接口（确认 / 改绑 / 关闭三动作）。
- 复用：医保上传走既有结算通道，院内码与厂商码同字段上传。
- 台账查询接口扩 source 枚举与核验状态展示。
> ⚠️ 接口路径、入参出参、流水号生成方案由开发补充。

### 5.3 非功能需求（按需激活）
- 性能：单次赋码生成 < 1s；批量 100 张生成 < 5s；补绑候选推荐 < 1s。
- 兼容：码签打印兼容 Windows 通用打印，不绑定特定打印机驱动。

## 七、开放问题与假设

**开放问题**
1. 中药饮片是否在医保豁免清单内，口径待医保办书面确认。
2. 院内码是否需要上传省级药品追溯平台，还是仅院内闭环。
3. 码签规格（尺寸/材质）与现有打印机型号是否兼容。
4. 门诊手动补绑的码上传医保时是否带「未实物扫码核验」口径，待医保办确认。
5. 赋码异常台账页为自主新增菜单，需向客户报备确认。

**假设清单**
- [假设] 院内码 20 位编码沿用现有追溯码规则，标识码段以 9 开头区隔（见 4.1 字段、5.1）。
- [假设] 拆零豁免标记由药品字典人工维护，本期不做自动判定（见 Non-Goals）。
- [假设] 医保上传通道可直接复用，无需新增结算接口（见 5.2）。
- [假设] 补绑推荐规则与药柜物理顺序一致时账实命中率最高，残余差异由盘点校准（见 4.4）。
