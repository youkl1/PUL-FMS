# PUL-FMS 采购到货单 PRD

> 范围：仅采购到货单及其直接相关约束；其他采购页面不展开。
> 口径：以原型现行代码为准（pul-fms-base-v1，2026-10-16 Round DD 后状态）。
> 版本：V1.2 · 2026-10-16 · Markdown 预览稿。
> 文档唯一性：本稿吸收原采购管理合并 PRD 的到货章节与共用扫码约束；历史设计稿、实施计划不作为现行依据。

---

## 一、背景与问题（Problem）

### 背景

PUL-FMS 以药品追溯码为主线串联采购、库存与后续流转。采购到货单是外部药品与追溯码进入院内库存的入口，库管员在本页完成「下载或手动建单 → 自动解析 → 扫码核对 → 审核生成已审核入库单」。

### 用户痛点

1. **到货验收环节多、跳页作业** —— 下载、解析、验收、审核分散时，库管员需要反复切换页面，作业慢且容易漏项。
2. **码不可用缺少闭环** —— 标识码未维护、库存码重复等异常若只提示不沉淀，单据会被卡住且没有明确处置入口。
3. **计划与实物容易失真** —— 下载码单、人工清单与实收数量若采用不同口径，会造成短收、多送或重复入库难以及时识别。

### 设计答案

| 痛点 | 设计答案 |
|---|---|
| 跳页作业 | 到货单一页走完下载 / 新增、自动解析、扫码核对与审核入库 |
| 码不可用缺少闭环 | 单内异常码页签 + 跨单异常码台账，维护或移除后恢复可审 |
| 计划与实物失真 | 数量 / 扫码总量双口径，药品清单、码详情、列表三层合计恒等，审核按守卫链拦截 |

## 二、用户故事（User Stories）

### 用户故事 1（P1）：下载供应商码单并审核入库

作为库管员，在供应商发货到达后，我希望从供应商平台下载码单，由系统自动解析并校验重复，扫码核对后审核入库，以便药品快速入账上架且追溯码全量进系统。

**独立验收：** 只做到货单页，库管员能完成「下载 → 解析 → 扫码 → 审核生成入库单」全流程。

**验收标准：**
- WHEN 选中平台未下载码单点「选中下载」，THE SYSTEM SHALL 按收货库房生成到货单并自动批量解析、校验库存码重复。
- IF 码单下载接口失败，THEN THE SYSTEM SHALL 生成「下载失败」单据并允许行内「重新下载」或「删除」释放码单池。
- WHEN 存在异常码（解析失败 / 库存码已存在）点「审核入库」，THE SYSTEM SHALL 弹窗拦截并给出去处置的快捷入口。

### 用户故事 2（P1）：手动登记无平台码单到货

作为库管员，在供应商未提供平台码单时，我希望手动新增到货单并选择扫码录入或清单录入，以便无下载条件的到货同样进入系统闭环。

**独立验收：** 手动单可保存、可扫码录入、可审核；手动单零核对一律拦截，须先扫码核对。

**验收标准：**
- WHEN 手动新增选择「扫码录入」并保存，THE SYSTEM SHALL 创建未审核单并直接打开统一扫码弹窗。
- WHEN 手动新增选择「清单录入」，THE SYSTEM SHALL 校验至少一个药品且数量大于等于 1，再保存计划清单。
- IF 手动单扫码总量为 0，THEN THE SYSTEM SHALL 拦截提交与审核并引导先扫码。

### 用户故事 3（P1）：异常标识码维护后恢复审核

作为库管员，在扫到未维护标识码时，我希望在异常码台账查到它正拦截哪些订单，通过追加药品字典绑定或人工补录完成处置，以便被拦截的到货单恢复可审核。

**独立验收：** 维护或人工补录完成后，相关到货单异常同源解除；字典维护场景回单据「重新解析」清零异常并放行审核。

**验收标准：**
- WHEN 解析失败行点「去维护」，THE SYSTEM SHALL 直跳药品字典维护页，回单据后支持「重新解析」。
- WHEN 未审核单的解析失败行点「编辑」并补齐五字段，THE SYSTEM SHALL 将人工补录码转正常码并同步解除列表、台账与审核拦截。
- WHEN 库存码已存在，THE SYSTEM SHALL 引导到扫码录入弹窗移除重复码，异常解除后方可审核。

## 三、方案概述（Solution）

> **核心功能一句话描述** —— 采购到货单一页走完「下载 / 新增 → 自动解析 → 扫码核对 → 审核入库」，审核直接生成已审核入库单，异常码通过维护、补录或移除形成处置闭环。

### 页面数据流

```text
供应商平台码单池（pch.platform）
        │ 下载单据 / 重新下载
        ▼
采购到货单（pch.arrive）←── 手动新增（扫码录入 / 清单录入）
        │ 自动解析 + 库存码重复校验
        │ 统一扫码弹窗（pur-in，暂存—提交制）
        │ 审核守卫链
        ▼
采购入库单结果记录（pch.inDocs）+ 库房在架集合推导
```

- 到货单页异常码台账是各未审核到货单单内异常的派生平铺视图，不另存第二份状态。
- 采购入库单仅作为本需求的审核输出与反审核回链，其页面操作不在本稿展开。

### 流程节点表

| 流程节点 | 页面 / 角色 | 用户行为 | 分支条件 | 异常去向 |
|---|---|---|---|---|
| 下载或建单 | 采购到货单 / 库管员 | 下载平台码单，或手动新增 | 下载接口是否成功 | 失败生成下载失败单，可重新下载或删除 |
| 自动解析 | 系统 | 校验码格式、标识码与库存重复 | 是否全部可解析且不重复 | 异常进入单内页签与派生台账 |
| 扫码核对 | 采购到货单 / 库管员 | 统一扫码弹窗录入或核对 | 清单归属、数量、占用是否通过 | 即时拦截或登记异常码 |
| 异常处置 | 异常码页签 / 台账 | 去维护、人工补录或移除 | 异常类型 | 处理后重新解析或同源解除 |
| 审核入库 | 采购到货单 / 库管员 | 提交审核并确认库房、库位、发票号 | 守卫链与盘点冻结是否通过 | 拦截并给出去处置入口 |
| 结果落账 | 系统 | 生成同号已审核入库单 | 单号幂等 | 已审核单禁止重复审核 |

### 升级点清单

- 5.1 采购到货单：筛选与列表、下载单据、手动新增、编辑、扫码录入、异常码台账、审核入库七个模块。
- 第四章为上述模块共用的扫码判定、清单数量、暂存提交与明细字段约束。

## 四、采购到货单共用扫码约束

> 本章约束适用于到货单的下载解析、扫码录入、异常处置与审核；各模块自己的流程树内嵌在第五章。

### 4.1 扫码判定主干（到货单）

每次回车扫码（支持逗号分隔批量码，逐码依次走本树），按固定顺序判定，命中即返回：

```
① 解析（单码解析判定树见 5.1，扫码链路分支）
     └─ 解析失败 → 单内登记异常码 → ×「请到药品字典/标识码补录」→ 结束
② 单据已完结？
     └─ 是 → ×「单据已完结，不能继续扫码」→ 结束
③ 本节点盘点中？
     └─ 是 → ×「本节点盘点中，禁止出入库」（纯拦截不留痕）→ 结束
④ 移除模式？（先于方向校验——入库场景要能移除「库存码已存在」冲突码）
     ├─ 是 · 码不在单 → ⚠「移除失败：该码不在本单」（不登记异常码）→ 结束
     └─ 是 · 码在单 → 剔除码记录 → ✓「已移除：药名 -N 单位」（折合回退、进度回落）→ 结束
⑤ 入库方向校验（码不得已在任何库存）
     ├─ 已在架 → ×「重复入库：该码已在「X」在架」→ 结束
     └─ 通过 ↓
⑥ 被其他未完结单占用？（共享占用池查重）
     └─ 是 → ×「被占用：该码已挂 XXX」→ 结束
⑦ 码源分支
     ├─ 有码单（拉取单核对）
     │    ├─ 码在单内 · 已核对过 → ⚠「重复验收：该码已核对过」→ 结束
     │    ├─ 码在单内 · 未核对 → 进入 4.2 清单判定
     │    └─ 单外码 → 占用校验后落 4.2：同药不超量→插入单内并直接标已核对（补扫口径）
     │                                        否则→单内异常码「不在码单内（多送/串货）」
     └─ 无码单（手动录入）
          ├─ 码已在单 → ⚠「重复扫码：该码已在清单」→ 结束
          └─ 新码 → 进入 4.2 清单判定
⑧ 落账：核对置位或建码记录（实时落盘草稿）→ ✓ 反馈 → 自动提交判定见 4.3
```

### 4.2 清单归属与超量判定树（主干第⑦步展开）

```
单据有计划清单？
├─ 无清单（自由扫码）
│    → 码驱动建药品行（自证行 planQty=null）+ 建完整码记录（checked=true）
│    → ✓「药名 +N 单位｜扫码数量 X」
│      （批次继承：在架记录 → 同单同药已填批次 → 码上解析值）
└─ 有清单
     ├─ 「按药品清单扫码」开关（仅「录入模式 + 有清单」可编辑；pre 有码单固定开；
     │    无清单人工单禁用并悬停注明原因；清单单默认=开、人工单默认=关）
     │    ├─ 开 · 药品不在清单 → ×「不在清单内：药名 不在本单药品清单」（即时拦截不留痕）
     │    └─ 关 · 清单外药品 → 码驱动建行放行（自证行）；清单内行超量仍拦
     ├─ 行级超量判定
     │    ├─ 行已备齐（未勾拆零）→ ×「超数量：药名 已备齐（X 盒），无需再扫」
     │    └─ 整码超出差额 → ×「需 Y（申请 N 片），已扫 X，本码盒码 +Z 瓶 = 超 W
     │                       （勾「拆零」可只取差额、余量回架）」
     └─ 勾「拆零」且整码超量？
          ├─ 是 → 只取差额（splitQty=差额×最小单位换算，split='是'），余量回架 → ✓
          └─ 否 → 整码入 → ✓「累计 X / Y（申请 N 销售单位）✓备齐」
```

### 4.3 扫码暂存-提交制（到货单共同外层）

```
每扫一码 → 只写会话草稿 scanDrafts[场景:单号]（工作副本与单据真身脱钩）
├─ 点「提交」→ 草稿整组写回单据池、清草稿；扫码总量为 0 不能提交
│    （toast「扫码总量为 0，不能提交——请先扫码」）；关闭弹窗草稿保留，
│    重开提示「已恢复上次未提交的扫码记录」，有草稿时底部亮橙「草稿待提交」标
├─ 点「清空重扫」→ 未提交部分回滚到已提交基线（已提交数据不受影响）
├─ 自动提交条件（有计划清单全部备齐 且 无异常码 且 预检通过）
│    → 扫中即自动写回 + toast「✓ 清单已备齐，扫码记录已自动提交」
└─ 单据页行内审核只认已提交数据
```

### 4.4 统一扫码弹窗明细区（字段口径）

统一扫码（scan-hub，弹窗 embed 与独立页同构）明细区 = 三页签，**页签均带括号统计值**：药品清单（清单行数）/ 码明细（码数）/ 异常码（异常数，非 0 红色加粗）。

1. **药品清单（11 列，与到货明细药品清单同字段）**：序号 / 药品名称 / 药品规格 / 生产厂家 / 批准文号 / 单价（元）/ 数量 / 扫码总量 / 差异 / 单位 / 金额（元）
   1. 数量 = 计划数量（销售单位）；扫码总量 = 已扫折合（有码单只计已核对码）；差异 = 数量-扫码总量出 ✓备齐/缺/超徽标 + 进度条；金额 = 扫码总量 × 单价（字典最新单价变更记录）
   2. 「按药品清单扫码」开关 = 关时扫入的清单外药品自动建行（自证行）：数量 / 差异显 —
2. **码明细（12 列，与到货明细码详情同字段同序）**：序号 / 药品追溯码 / 药名通用名 / 码层级（一/二/三级码）/ 父级码（恒 —）/ 生产批次 / 生产日期 / 有效期至 / 扫码数量 / 核对状态 / 标识码 / 发码机构（码上放心 / GS1 / IDCODE）
   1. 扫码数量 = 该码已核对才计单码折合（未核对 = 0），与药品清单扫码总量合计恒等
   2. 核对状态：到货单按 checked 展示（已核对绿 / 未核对灰）
   3. 到货单录入 / 采购入库核对模式补「操作」列（行内移除）
3. **异常码**：扫码异常（解析失败 / 不在码单 / 被占用）集中登记，处理后「移除」放行审核（审核硬拦见 5.1）

### 4.5 数据产物（码记录 / 异常码记录）

| 字段（codes[]） | 说明 | 生成时机 |
|---|---|---|
| code | 追溯码原文（阿里 20 位 / GS1 / IDCODE） | 扫码 / 下载 |
| checked | 是否已核对（true=计入扫码数量） | 有码单核对扫中=true；录入模式建行即 true |
| time | 核对时间 | 核对 / 建行时 |
| split / splitQty | 拆零标记 / 拆零数（拆零单位） | 勾「拆零」扫码时 |
| batch / prodDate / expDate | 批次 / 生产日期 / 效期 | 继承在架或同单同药批次；GS1 / IDCODE 从码上带回 |
| location | 库位 | 审核落账时补 |
| manualFix | 人工补录标记（'是'=异常码页签行内「编辑」补录五字段保存后转正常码，异常统计/审核硬拦同源豁免） | 人工补录保存时 |

异常码记录 `badCodes[]`：`{code, reason, time}`——reason 决定处置（解析失败→「去维护」补录字典或行内「编辑」人工补录；库存码已存在→扫码录入移除；不在码单内→移除）。

## 五、功能需求（Feature Requirements）

## 5.1 采购到货单（到货全流程一页走完）

### 页面目的

库管员在本页完成供应商到货的**全部验收动作**：拉取码单或手动建单 → 系统自动解析、校验库存码重复 → 扫码核对 → 审核生成已审核入库单（码入在架）。审核后的入库作业由「采购入库单」承接。

---

#### 模块 1｜筛选与列表

**筛选栏**（文本标签 + 控件，`查询` / `重置`）：

| 筛选项 | 控件 | 匹配 |
|---|---|---|
| 单据编号 / 发票号 / 发货方 / 收货方 | 输入框 | 包含 |
| 收货库房 | 下拉（全部 + 库房清单） | 全等 |
| 来源 | 下拉（全部 / 拉取 / 手动） | 全等 |
| 异常 | 下拉（全部 / 下载失败 / 解析异常 / 无异常） | 解析异常不含下载失败单；无异常需两者皆否 |
| 异常信息 | 输入框 | 同「异常信息」列口径文本包含 |
| 审核 | 下拉（全部 / 未审核 / 已审核） | 全等 |
| 单据时间 | 日期起止 | 按单据时间前 10 位 |

**列表 15 列**（无分页；未确认行红底，选中行高亮）：

| 列 | 说明 |
|---|---|
| 序号 / 单据时间 / 发货方 | — |
| 单据编号 | 加粗 |
| 单据类型 | 固定值「采购到货」 |
| 收货方 | 固定「中心院区」 |
| 收货库房 | + 库位小字换行 |
| 发票号 | 空显 — |
| 来源 | 徽标：手动·清单🟠 / 手动·扫码🟠 / 拉取🔵 |
| 数量 | 清单录入单=Σ计划清单（人工输入）；拉取单=全码折合（下载即定计划）；手动扫码单显 — |
| 扫码总量 | 已核对码折合（计算单位层，含箱码按换算链展开；人工补录码按 1 计入）——与药品清单「扫码总量」合计、码详情合计三层恒等 |
| 审核 | 已审核🟢 / 未审核⚪ |
| 异常状态 | 已审核=—；下载失败🔴；解析异常🔴（异常码>0）；无异常🟢 |
| 异常信息 | 已审核=—；下载失败🔴（含接口错误）；「解析失败×N；库存码已存在×N」红链接（点击跳异常码页签）；无异常=— |
| 操作 | 按行状态三分支，见下 |

**操作列**（行内按钮恒可点、点入判定）：

| 行状态 | 按钮 |
|---|---|
| 已审核 | —（无操作） |
| 下载失败 | `重新下载`（从码单池补齐码、置成功；重试必成功）+ `删除` |
| 未审核且下载成功 | `扫码录入` / `审核入库`（主按钮）/ `编辑` / `删除`（仅手动单且扫码数=0 显示） |
| 行点击 | 选中该单，刷新明细区 |

**流程树｜删除到货单**

```
单据状态？
├─ 下载失败行 → 确认删除 → 码单池恢复「未下载」（可重拉）
```

### 页面数据流程

1. **输入（读）**：`pch.arrive`（列表主数据与单内异常）/ `pch.platform`（下载弹窗）/ `pch.inDocs`（库存码重复判定）/ 药品字典（三格式解析）；异常码台账由未审核到货单派生
2. **处理**：下载快照码 → 批量解析（未维护→单内异常并汇入派生台账）→ 库存码重复校验 → 扫码核对（草稿制）→ 审核守卫链
3. **输出（写）**：下载 / 新增 / 编辑 / 删除 → `pch.arrive`（删除失败单同步恢复 `pch.platform`）；审核 → 到货单翻转 + `pch.inDocs` 新增；维护 → 药品字典（PUL_DRUG.upsertFromFix）+ 回单重新解析；人工补录 → 单内码记录 `manualFix='是'`
4. **下游**：入库单在「采购入库单」页出现；在架库存 / 台账 / 流向查询随之更新；反审核后本单回「未审核」

### Non-Goals（本次明确不做）

1. 不展开采购入库、采购退货及查询页面的需求，仅保留到货审核输出与反审核回链。
2. 不做到货退货；到货未入库错单按现行删除规则处理。
3. 不做扫码设备管理；扫码枪与高拍仪按 HID 输入处理。
4. 不另建与单内异常分离的第二套异常码状态；台账只做到货单异常派生视图。

## 六、技术与数据需求

### 6.1 数据与业务逻辑

1. **数据池**（store 命名空间 `pch`，sessionStorage 会话级持久化）
   1. `arrive`：到货单列表主数据，审核状态由 `downloaded` 推导。
   2. `platform`：供应商平台码单池，`pulled` 表示已下载，`dlFail` 为失败演示标记。
   3. `inDocs`：审核输出结果记录，只由到货审核生成；反审核回链不在本稿展开。
   4. 到货单异常码台账：各未审核到货单单内异常逐码汇集的派生视图，不独立写状态。
   5. 药品字典：PUL_DRUG 主子表为唯一事实源，标识码字典视图由字典刷新。
2. **码解析三格式归一**：阿里 20 位（标识码 7 + 序列 9 + 校验 4）、GS1（`01` 开头）、IDCODE（`MA.` 开头）；后两者归一后查字典，未命中进入解析失败异常。
3. **标识码字典约束**：一条药品可绑定多条标识码；阿里码以前 7 位为键。字典字段包括 `idcode` / `drugCode` / `level` / `packUnit` / `packSpec` / `ratio` / `status`。
4. **码与单位约束**：
   1. `DRUGS.baseUnit` 为库存基本单位，一级码对应基本单位；`saleUnit` 为 HIS 结算单位，`minUnit` 及换算链用于拆零和折合。
   2. 计划数量可按销售单位展示，备齐、差异、扫码总量与审核一致性统一折合到库存基本单位计算。
   3. 列表扫码总量、药品清单扫码总量、码详情折合合计三层恒等。
5. **快照与短收**：下载时平台码单快照到到货单；审核时仅已核对码快照到入库单，未扫残留码留在到货单作短收记录。
6. **库存约束**：库房在架由已审核单据集合推导，不在追溯码上冗余状态字段；审核入库单是集合推导加项。架构依据见 [TRACE_CODE 不设 status 字段 ADR](../../../../../docs/decisions/2026-09/2026-09-28-no-status-field-on-trace-code.md)。
7. **审核守卫顺序**：异常码硬拦 → 拉取单零核对直接审批翻转 → 扫码总量为 0 硬拦 → 计划与扫码一致性校验 → 盘点冻结校验；行内审核按钮恒可点、点入判定。
8. **扫码暂存提交**：扫码先写会话草稿，提交后写回单据；扫码总量为 0 不能提交，单据页审核只认已提交数据。
9. **会话迁移与演示数据**：老会话经 migrate 无损升级；演示种子按大场景收敛为 6 张到货单，提供「⟲ 重置」恢复种子态。

### 6.2 接口诉求（PM 业务层）

1. 供应商平台码单接口：按时间段、供应商等条件拉取码单列表与逐码明细，支持失败重试；单张千码级码单应秒级完成。
2. 审核入库与 HIS 推送：到货审核单事务、单号幂等，生成单据头与已核对码明细；HIS 推送需支持状态回查与失败重试。
3. 标识码字典维护：支持从中继平台单向拉取最新标识码，以及向药品字典子表追加绑定。
4. ⚠️ 以下内容由开发补充：接口路径、入参出参、缓存、幂等与真实 GS1 / IDCODE 映射规则。

### 6.3 非功能需求

1. 权限：到货单菜单与按钮按角色控制；KEEPER 库管可查看、新增、下载、扫码、审核，CHECKER 收验可扫码。
2. 隔离：列表数据按登录库房隔离，收货库房默认当前登录库房。
3. 兼容：老会话 sessionStorage 经 migrate 无损升级；扫码枪与高拍仪回车触发，支持逗号分隔批量码。
4. 性能：千码级下载与解析应秒级完成；码明细长列表保持滚动与筛选可用。
