# 箱码全链路 · 表存储实例

> 日期：2026-09-23
> 用途：配合图 12（表结构 ER）看懂「扫一箱码」时每张表实际长什么样
> 口径：库存只存一级码（盒）；箱码是钥匙，扫到即按换算链展开；片没有独立追溯码

贯穿药：**阿莫西林胶囊 0.25g**

## 基础单位在哪？（先看这个）

**不在追溯码里，也不在标识码里。** 库存基本单位 `baseUnit` 写在 **药品主表 DRUGS**，等于换算链 `units` 的链尾（eq=1 的那一档）。

| 概念 | 存在哪张表 | 字段 | 本例 | 是不是「最小销售包装」 |
|------|------------|------|------|------------------------|
| 库存基本单位 | 药品主表 DRUGS | baseUnit | 盒 | 设计上应当等于最小销售包装 |
| 最小销售包装 | 标识码子表 IDCODES | level=1 那条的 packUnit | 盒 | 是。应当 = DRUGS.baseUnit |
| 本码包装层级 | 标识码子表 IDCODES | packUnit + level | 箱 / 盒 | level=2 是箱，不是基本单位 |
| 追溯码实例 | 追溯码 TRACE_CODE | **无单位字段** | 20 位编号 | 前 7 位去查标识码，再关联药品做换算 |
| 拆零单位 | 药品主表 DRUGS | minUnit | 片，1盒=7片 | **不是**基本单位；片没有独立追溯码 |

一句话：**药定基本单位，码定包装层级，追溯码只是实例编号。** 约定「1 个一级码 = 1 个基本单位」，所以在架码的行数 = 药的盒数。

可视化页面：`13-box-instance.html`（与本文件同目录）（图纸清单 #13，含码转全流程图）。

---

| 换算 | 值 |
|------|----|
| 1 箱 | 60 盒（库存基本单位） |
| 1 盒 | 7 片（拆零最小单位，只在药房拆） |

供应商发货确认的是 **60 个一级盒码**（箱码只作父码 `code2`）。医院下载到货单时已经是 60 行，入库不再展开。

场景节奏：

0. 采购到货（监管平台拉取；发货时客户已确认 60 个一级盒码）
1. 采购入库（核对拷贝，不再展开；审核后入在架）
2. 领用出库（药房申请 2 盒）
3. 药房入库（领用单闭环）
4. 药房拆零发药（打开 1 盒，发出 2 片）——后段推荐口径，原型尚未落地

约定：

- 表名写成「中文名 `ENGLISH`」
- 每张表上方一行注释：这张表干什么、本步动不动
- 单元格里的 `← 注释` 是给人看的，不是字段值
- 60 行只展开头 2 + 尾 1，中间用省略行

### 3.5 追溯码实例 `TRACE_CODE`（本步 0 增删）

**不删行、不改 status**（没有这个字段）。那 60 行还在。

库存怎么变：

```
在架 = 已审核采购入库码 − 已出库码
     = 60 个盒码 − {…0001, …0002}
     = 58 盒

在途 = 领用出库单 status='已出库' 且尚未药房入库的码
     = {…0001, …0002}
     = 2 盒
```

同一条码可以同时出现在入库单的 `DOC_CODE` 和出库单的 `DOC_CODE` 里——这就是「码随单转」。

## 6. 五个时刻对照（只看库存相关）

| 时刻 | ARRIVE_CODE | TRACE_CODE 行数 | 库房在架 | 在途 | 药房整盒 | 药房已拆 |
|------|-------------|-----------------|----------|------|----------|----------|
| ⓪ 到货拉取后 | 60 | 0 | 0 | 0 | 0 | — |
| ① 采购入库审核后 | 60（已下载） | 60 | 60 盒 | 0 | 0 | — |
| ② 领用出库审核后 | 60 | 60（不删行） | 58 盒 | 2 盒 | 0 | — |
| ③ 药房确认入库后 | 60 | 60 | 58 盒 | 0 | 2 盒 | — |
| ④ 拆零发 2 片后 | 60 | 60 | 58 盒 | 0 | 1 盒 | 1 盒（剩 5 片） |

推导公式（与图 08 一致，本例只用到的项）：

```
库房在架 = 采购入库(已审核) − 领用出库(已出库或已闭环) − 其他出库 − 损耗 − 采购退货
在途     = 领用出库单 status='已出库'
药房库存 = 领用出库单 status='药房已入库' − 发药出库 − 退回
```

## 8. 和原型脚本的对应

| 本文表 | 原型里的位置 |
|--------|----------------|
| `DRUGS` / `IDCODES` | `scripts/drug-data.js` → `PUL_DRUG` |
| `TRACE_CODE` 集合 | 不落单表；由 `wh-data.js` 的 `stockAll()` 按单据加减推导 |
| `ARRIVE` / `ARRIVE_CODE` | `purchase-data.js` → `pch.arrive` / `codes[]` |
| `ARRIVE_LINE` | 不落表；`PUL_PCH.summarize()` 按标识码+批次聚合 |
| `DOC` 采购入库 | `purchase-data.js` → `pch.inDocs` |
| `DOC` 领用出库 | `wh-data.js` → `wh.pickDocs` |
| `DOC_CODE` | 各单据内嵌 `codes[]` |
| `REQ` / `REQ_ITEM` | `wh-data.js` → `wh.reqPool` / `items[]` |
| 发药拆零 | 后期待设计；`split` / `splitQty` 字段已在码记录上预留 |

本例药品「阿莫西林」是为讲清箱→盒→片专门构造的，与种子药「加罗新 1 箱=60 瓶」同构，数字更好算。
