## 一、第一性原理：物理世界只发生一件事（总）

**药在搬家。** 供应商的仓库 → 医院的库房 → 药房的药架 → 病人手里；偶尔也往回搬（退货、退库、退药）。搬家就是全部真相——系统里的单据、码、库存数字，都只是搬家的记录：

- **单据 = 搬家的凭证**。每搬一次开一张单，单只是证明「这件事发生过」。
- **码 = 每盒药的身份证**。一盒一码，终身不变；药到哪，码跟到哪。
- **库存 = 拿码算出来的**。进来的码 − 出去的码，不是存出来的。

正向七件事、逆向三件事，每件事配一张凭证：

| | 物理事件 | 方向 | 凭证（单据） | 账动不动 |
|---|----------|------|--------------|----------|
| E1 | 供应商发货，货到医院门口 | 供应商 → 库房 | 到货单 | 不动账——货还只是「在路上」 |
| E2 | 验收、上架，药进库房 | 进库房 | 采购入库单 | **审核后开始占库存** |
| E3 | 药房说「我要药」 | 药房 → 库房（一句话） | 领用申请单 | 不动账——只是计划，可跳过 |
| E4 | 库房拣货、装箱 | 库房内 | 不产生单据 | 不动账——药还在库房 |
| E5 | 药离开库房 | 库房 → 药房 | 领用出库单 | **审核即扣账**，此后叫「在途」 |
| E6 | 药房收货点收 | 进药房 | 领用单闭环 | 数量不变，只改归属 |
| E7 | 药发到病人手里 | 药房 → 病人 | 处方 / 发药单 | 整盒码随单走；拆零记在盒码上 |
| R1 | 药退给供应商 | 库房 → 供应商 | 采购退货单 | 码随单离开在架 |
| R2 | 药房把药退回来 | 药房 → 库房 | 退回出库单 + 退回入库单 | 码回库房在架 |
| R3 | 病人退药 | 病人 → 药房 | 处方退药单 | 码回药房在架 |

**因果链只有一条：** 到货 → 入库 →（申请 → 备货 →）审核出库 → 收货 → 发药。申请和备货可以没有，审核出库和收货必须有。逆向三张单是正向的镜像——药往回搬，公式不用改，退货单、退库单、退药单都只是「出去的码」。

供应商发货确认的是 **60 个一级盒码**（箱码只作父码 `code2`）。医院下载到货单时已经是 60 行，入库不再展开。

## 三、三条铁律（总）

看懂这三句，后面的表全是它们的印证。

### 铁律一 · 码上不带单位（基础单位在药品主表）

**不在追溯码里，也不在标识码里。** 库存基本单位 `baseUnit` 写在 **药品主表 DRUGS**，等于换算链 `units` 的链尾（eq=1 的那一档）。

| 概念 | 存在哪张表 | 字段 | 本例 | 是不是「最小销售包装」 |
|------|------------|------|------|------------------------|
| 库存基本单位 | 药品主表 DRUGS | baseUnit | 盒 | 设计上应当等于最小销售包装 |
| 最小销售包装 | 标识码子表 IDCODES | level=1 那条的 packUnit | 盒 | 是。应当 = DRUGS.baseUnit |
| 本码包装层级 | 标识码子表 IDCODES | packUnit + level | 箱 / 盒 | level=2 是箱，不是基本单位 |
| 追溯码实例 | 追溯码 TRACE_CODE | **无单位字段** | 20 位编号 | 前 7 位去查标识码，再关联药品做换算 |
| 拆零单位 | 药品主表 DRUGS | minUnit | 片，1盒=7片 | **不是**基本单位；片没有独立追溯码 |

20 位码的拆法：`6934180`（标识码 7 位 → 查 IDCODES）+ `000000001`（序列号 9 位）+ `0001`（校验 4 位）。

一句话：**药定「按什么算账」，码定「是哪层包装」，追溯码只是「哪一盒」。** 约定「1 个一级码 = 1 个基本单位」，所以在架码的行数 = 药的盒数。

### 铁律二 · 库存是算出来的：在架 = 进来的码 − 出去的码

- **正向 · 扫一个码**：扫码枪读 20 位 → 前 7 位查标识码 → 查到药品主表。立刻知道这码**是什么药、哪层包装、折几盒**。入库、出库、盘点都靠它。
- **反向 · 问一种药**：问「阿莫西林还剩几盒」→ 找出它所有的码 → **扣掉已经随出库单走掉的** → 剩下几行就是几盒。

**一句话公式：在架 = 进来的码 − 出去的码。** 进来的看已审核入库单，出去的看已审核出库单。已出库但药房还没点收的，叫「在途」。TRACE_CODE 只增不删、也不打状态——同一条码会同时出现在入库单和出库单上，这叫「码随单转」。文末「五时刻对照表」就是这个公式的逐步推演。

### 铁律三 · 没有 status 字段：流水为王，缓存为奴

库存不是一件「东西」，是过去所有单据算出来的结果。给它单存一个 status，等于把算好的数再抄一份——抄出来的副本就是缓存，缓存会跟真账对不上。加不加缓存，用三问判断：

| 缓存三问 | 纯推导（本设计） | 加 status 字段 |
|----------|------------------|----------------|
| 查询成本 | 集合差，毫秒级（在架 10⁵ 码规模） | O(1) 点查，但省的不是瓶颈 |
| 一致性 | **天然一致——没有第二份数据可错** | 审核双写（单据+码状态），写一半崩 = 静默错账 |
| 可重建 | 无需重建 | 能重建，但得先发现它错了 |

**就像银行账户：** 流水是真账，余额是照着流水算的。银行敢存余额，是因为养了一整套对账的人盯着它别算错。我们干脆不存余额——余额永远现算，就永远不用跟自己对账（跟 HIS、监管平台那种跨系统对账照做）。

**但不是一刀切。** 有些字段就是缓存，比如 `location`（在哪）、`splitQty`（拆零剩几片）——它们是「单码高频点查」，每次现算太亏。而在架 / 在途是「集合加减」，SQL 本来就算得快，保持现算。代价也得认：① 推导只写一个函数，全系统复用；② 每加一种单据，登记它是加还是减；③ 出库审核前现查这码刚动过没，防重复出库。

**什么时候再回头加缓存：** 跨院区看板要秒开、流水破千万行、外部系统老来查、盘点要锁快照。到那时加物化视图 + 对账任务，但记住 **「流水为王，缓存为奴」**：缓存随时能删了重建，流水一行都不许改。完整论证见 `docs/decisions/2026-09/2026-09-28-no-status-field-on-trace-code.md`。

### ↩ 逆向 · 退货给供应商

- **物理上**：药从中心库搬回供应商——近效期、质量问题，或供应商召回。
- **凭证**：**采购退货单**，采购入库单的镜像（原型：采购退货单页）。
- **码怎么动**：退货单绑哪些盒码，哪些码就随单离开在架。`TRACE_CODE` 照旧不删行、不改状态。
- **库存变几**：不用改公式——退货单也是「出去的码」。在架 = 进来的码 − 出去的码，自动变少。

## 五、第二段路 · 库房 ⇄ 药房 / 病区（分）

> 段首四问：物理上——药从中心库搬到门诊药房（病区同构，对库房都是「领用方」），也可能搬回来（退库）；凭证——申请单（可选）→ 领用出库单 → 收货闭环；码——出库审核后离开在架进在途，收货后 location 改药房货位；库存——库房 60 → 58，在途 2 → 0，药房 2 盒。
> 因果链：**申请（可选）→ 备货拣货（不动账）→ 审核出库（扣账时点）→ 药房收货（闭环）。**

### 2.1 领用出库 · 药房申请 2 盒（扣账时点）

### ↩ 逆向 · 药房退库

- **物理上**：领错、多用或停用的药，从药房搬回库房。
- **凭证**：两张接力——**退回出库单**（药房开出，扫码确认出库）→ **退回入库单**（库房核对回架）。和正向「领用出库 → 药房收货」正好镜像。
- **码怎么动**：码的 location 从药房货位（M-01）改回库房库位（A-01-02）。不删行、不改状态。
- **库存变几**：库房在架自动回升、药房在架自动减少——还是那句公式。

## 六、第三段路 · 药房 ⇄ 病人（分）

> 段首四问：物理上——药从药架到病人手里，也可能退回来；凭证——处方 / 发药单，退回用处方退药单；码——整盒发码随单走，拆零发在原盒码上记剩余；库存——药房 2 盒 → 1 整盒 + 5 片。
> 特殊之处：**片没有身份证**（没有独立追溯码），拆零不能把 1 个盒码拆成 7 行，只能在原盒码上记「还剩几片」。

### 3.1 拆零发药 · 打开 1 盒发出 2 片（推荐口径，待设计）

前提：片 **没有** 独立追溯码。不能把 1 个盒码再展开成 7 行 `TRACE_CODE`。

### ↩ 逆向 · 病人退药

- **物理上**：药从病人手里退回药房——医嘱变更、不良反应等。
- **凭证**：**处方退药单**——选已发处方、核对码清单、确认退药，处方改「已退药」。
- **码怎么动**：整盒未拆 → 码直接回药房在架；已拆零的片 → 数量回补到盒码 splitQty 上。
- **注意**：能不能再发由药师看外观与效期人工判定；不可再用的走损耗、不回在架。

## 七、五个时刻对照（总）

盯住两列就够：TRACE_CODE 永远 60 行（只增不删）；「库房在架」就是那句公式——进来的 − 出去的。

| 时刻 | ARRIVE_CODE | TRACE_CODE 行数 | 库房在架 | 在途 | 药房整盒 | 药房已拆 |
|------|-------------|-----------------|----------|------|----------|----------|
| 1.1 到货后 | 60 | 0 | 0 | 0 | 0 | — |
| 1.2 入库审核后 | 60（已下载） | 60 | 60 盒 | 0 | 0 | — |
| 2.1 出库审核后 | 60 | 60（不删行） | 58 盒 | 2 盒 | 0 | — |
| 2.2 药房收货后 | 60 | 60 | 58 盒 | 0 | 2 盒 | — |
| 3.1 拆零发 2 片后 | 60 | 60 | 58 盒 | 0 | 1 盒 | 1 盒（剩 5 片） |

推导公式（与图 08 一致，本例只用到的项）：

```
库房在架 = 采购入库(已审核) − 领用出库(已出库或已闭环) − 其他出库 − 损耗 − 采购退货
在途     = 领用出库单 status='已出库'
药房库存 = 领用出库单 status='药房已入库' − 发药出库 − 退回
```
