# PUL-FMS 基础平台骨架 — UI 框架复用说明

> 本文件回答一个问题：**这套原型哪里用了 Tabler、哪里没用、为什么、怎么验证。**
> 原则：优先复用框架 UI，框架没有/不适用的才自写，自写部分沿用 Tabler 视觉语言。

## 一、用了 Tabler 的部分（内容区 100% 框架件）

Tabler 1.5.1 已本地化到 `prototypes/shared/tabler/`（不依赖外网 CDN），内容区组件全部用真 Tabler 类：

| 组件 | Tabler 类 | 用在哪 |
|------|-----------|--------|
| 表格 | `table table-vcenter card-table table-hover` | 角色/用户/院区/字典各列表 |
| 卡片 | `card / card-header / card-body / card-footer` | 所有内容区块 |
| 按钮 | `btn btn-primary / btn-outline-* / btn-sm` | 全部操作按钮 |
| 徽标 | `badge bg-blue-lt / bg-green-lt / bg-secondary-lt` | 状态、角色、节点类型 |
| 表单 | `form-control / form-select / form-check / form-label` | 筛选条、弹窗输入 |
| 栅格 | `row / col-* / g-3` | 弹窗与卡片布局 |
| 图标 | Tabler Icons SVG 路径 | 侧栏与顶栏图标 |

## 二、没用 Tabler 的部分（框架空白，自写）

| 部位 | 为什么不用 Tabler | 自写在哪 |
|------|------------------|----------|
| 侧栏 + 顶栏壳 | Tabler 的 `.navbar-vertical` 在 ≥768px 时是 `position: fixed` 锚定整个浏览器视口，无法嵌进我们 1440px 的预览容器 | `styles/tabler-preview.css` 的 `.app-*` 系列，颜色/圆角/动效对齐 Tabler 暗色侧栏（#182433 / #206bc4 / 6px / 150ms ease-out） |
| 权限树（菜单树 / 院区库房树） | Tabler 是纯 CSS 库，**没有树组件** | `styles/roles.css` 的 `.ptree` + `scripts/roles.js` 的 `bindPtree`（父子联动、半选态），两种树复用同一组件 |
| 侧栏折叠（mini 侧栏） | Tabler 1.5.1 **没有 mini-sidebar 组件** | `.app-page.folded` 系列样式 + 顶栏折叠按钮，默认折叠，会话内记忆 |
| 扫码弹窗（扫码枪模拟器） | Tabler **没有「连续扫码 + 逐条 ok/warn/bad 反馈」组件**（modal 本身用 Tabler 结构，反馈列表自写） | `styles/purchase.css` 的 `.pch-scan-*` + `scripts/purchase-shared.js` 的 `PchUI.openScan`，采购/库房 9 页复用同一组件 |
| 步骤条 / 状态灯 | Tabler **没有步骤条组件**；状态灯是原型专属语义件 | `styles/purchase.css` 的 `.pch-steps / .pch-light` |
| 库房统计条 / 效期徽标 / 备货双层布局 / 单位切换 | Tabler **没有统计条、效期三档徽标、药品明细⇄码清单双栏布局、单位切换开关** | `styles/wh.css`（`.wh-stats / .wh-exp-badge / .wh-pick-grid / .wh-unit-toggle`），文件头注释已注明「框架无此组件」 |

### 3.2 数据层（本轮关键取舍）

- **`scripts/drug-data.js`（PUL_DRUG）** — 药品字典主子表成为**唯一事实源**：主表 DRUGS（units 换算链 U3→U0、minUnit 拆零最小单位）+ 子表 IDCODES（7 位标识码 + 等级 + 包装规格）。`flat()` join 成老 `pch.dict` 形状，采购模块 20 处 `S.dict` 调用**零改动**透明切换。
- **`scripts/purchase-data.js`** — load() 时把 `s.pch.dict` 刷新为 `PUL_DRUG.flat()` 内存视图；`bad-codes.js` 维护写入改走 `PUL_DRUG.upsertFromFix`。
- **`scripts/wh-data.js`（PUL_WH）** — 库房在架库存**不加 status 字段**，用集合推导：在架 = 采购入库（已审核）+ 其他入库（已审核）+ 退回入库（已审核）− 采购退货（已审核）− 领用出库 − 其他出库（已审核）− 损耗（已审核）。在途 = pickDocs `status='已出库'` 单列。

## 四、怎么验证"真的用上了 Tabler"

1. **F12 看类名**：右键任意表格/按钮/卡片 → 检查 → class 里是 `table`、`card`、`btn btn-primary` 等 Tabler 类名。
2. **F12 Network 看加载**：刷新页面，能看到 `tabler.min.css`（约 693KB，本地文件）返回 200。
3. **抽掉即裸奔**：临时删掉页面 `<link ... tabler.min.css>` → 内容区立刻变成无样式的裸 HTML（侧栏不受影响，因为壳是自写的）。这是最有效的反向验证。

## 共享单据明细组件 PulDocDetail（scripts/doc-detail.js）

单据页「药品清单 / 码详情 / 异常码」公共表格 + 页签组件。纯视图：输入标准化 model 返回 HTML，`bind` 只转发事件——不保存、不审核、不读写业务数据。

**五个 API**

- `renderTabs(model, options)`：卡片壳 + 页签（药品清单/码详情/异常码），活动页签由 `model.activeTab` 控制，`model.empty=true` 走未选单空态（不渲染表格）；
- `renderDrugs / renderCodes / renderBad(model, options)`：独立表格（不套卡片壳），供页面自行嵌入卡片；
- `bind(root, handlers)`：转发页签点击（`handlers.onTab`）与操作按钮（`handlers.actions[action]({action, table, index, row, event})`），disabled 按钮不触发、缺回调明确抛错。

**契约要点**

- 列即契约：drugs 默认 11 列 / codes 默认 12 列 / bad 默认 6 列（列名与顺序是跨页面契约），`columns` 可从注册表裁剪，未知列抛错；页面专属列走 `extraColumns`（必须带 `cell` 函数）；
- `names`：仅允许 drugs/codes/bad 三个 key，只覆盖页签显示名（esc 转义、计数括号仍组件生成），用于「无库存码」等改名；
- `counts`：`'rows'`（默认，按行数）与 `'scanQty'`（累加行 scanQty，两位取整对齐 fmtN）两种计数模式；
- `panelActions`：异常码面板级操作，字符串或 `{key, disabled:true}`（输出原生 disabled）。

**硬规则**：新页面 / 改既有页**禁止自写药品、码、异常码公共表格与页签拼接**，一律走本组件（呼应 `.claude/guides/pul-fms-doc-page-conventions.md` §1「先查共享层，禁止重造」）。接入方式：`purchase-shared.js` 之后、页面脚本之前加载 `scripts/doc-detail.js?v=20261016-1`（仅一次）。

**零逻辑变化约束**：采购到货（purchase-arrive）与统一扫码（scan-hub / scan-hub-ui）收编仅替换表格/页签渲染，原业务函数（docBad、goScan、reparseSel、HUB.ctxOf、SC.* 等）逐个保留并纳入回归断言，任何收编不得改变业务行为。

**20 页收编清单**：purchase-arrive / purchase-out / purchase-in / wh-other-in / wh-other-out / wh-pick / wh-pick-out / ph-req / ph-req-in / ph-ret-out / scan-hub / scan-lab / disp / tray / wh-return-in / wh-loss-out / ph-loss / rx-ret / tray-ret / ward-sign（quick-scan / ph-scan-in 为跳转壳不在内）。防回退断言集中在 `scripts/_t-doc-detail.node.js` §12–§18：20 页名单枚举对比 + 逐页接线检查（加载顺序/仅一次），任一页从清单遗漏即 FAIL。

**验证**：在 pul-fms-base-v1 目录跑 `node scripts/_t-doc-detail.node.js`（组件契约 + 20 页接线 + 测试壳 + 仓库级手拼清扫防回退全量回归）。

**范围豁免（§19 清扫白名单，登记理由方可自写表格）**：弹窗选择列表（选在架码 / 码列表 / drug-picker / rx-bind）、查询页（\*-q / query / stock / trace / flow）、台账与字典（bad-codes / purchase-detail / drug / idcode / ledger）、跳转壳遗留（quick-scan / ph-scan-in）、盘点域（inv / inv-gain / inv-loss，未收编后续评估）、purchase-arrive poolDetailHtml 码单池预览。

**已知留档**：① purchase-arrive 码页签 scanQty 计数与 scanTotalNum 在「清单单存在未核对码」等当前不可达状态下存在理论口径差（现业务落库即 checked=true）；② 「移除」按钮存在 secondary（组件注册表）与 danger（ph-loss / wh-loss-out / wh-return-in 行内 extraColumns）两种颜色变体，label 已统一；③ 组件 money() 不格式化字符串数值、countOf 对非有限 scanQty 静默跳过（入参契约：数值）。
