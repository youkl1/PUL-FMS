# PUL-FMS 基础平台骨架 — UI 框架复用说明

> 本文件回答一个问题：**这套原型哪里用了 Tabler、哪里没用、为什么、怎么验证。**
> 原则：优先复用框架 UI，框架没有/不适用的才自写，自写部分沿用 Tabler 视觉语言。

## 一、用了 Tabler 的部分（内容区 100% 框架件）

Tabler 1.5.1 已本地化到 `prototypes/shared/tabler/`（不依赖外网 CDN），内容区组件全部用真 Tabler 类：

| 组件 | Tabler 类 | 用在哪 |
|------|-----------|--------|
| 表格 | `table table-vcenter card-table table-hover` | 角色/用户/院区/字典各列表 |
| 卡片 | `card / card-header / card-body / card-footer` | 所有内容区块 |
| 按钮 | `btn btn-primary / btn-outline-* / btn-sm` | 全部操作按钮 |
| 徽标 | `badge bg-blue-lt / bg-green-lt / bg-secondary-lt` | 状态、角色、节点类型 |
| 表单 | `form-control / form-select / form-check / form-label` | 筛选条、弹窗输入 |
| 栅格 | `row / col-* / g-3` | 弹窗与卡片布局 |
| 图标 | Tabler Icons SVG 路径 | 侧栏与顶栏图标 |

## 二、没用 Tabler 的部分（框架空白，自写）

| 部位 | 为什么不用 Tabler | 自写在哪 |
|------|------------------|----------|
| 侧栏 + 顶栏壳 | Tabler 的 `.navbar-vertical` 在 ≥768px 时是 `position: fixed` 锚定整个浏览器视口，无法嵌进我们 1440px 的预览容器 | `styles/tabler-preview.css` 的 `.app-*` 系列，颜色/圆角/动效对齐 Tabler 暗色侧栏（#182433 / #206bc4 / 6px / 150ms ease-out） |
| 权限树（菜单树 / 院区库房树） | Tabler 是纯 CSS 库，**没有树组件** | `styles/roles.css` 的 `.ptree` + `scripts/roles.js` 的 `bindPtree`（父子联动、半选态），两种树复用同一组件 |
| 侧栏折叠（mini 侧栏） | Tabler 1.5.1 **没有 mini-sidebar 组件** | `.app-page.folded` 系列样式 + 顶栏折叠按钮，默认折叠，会话内记忆 |
| 扫码弹窗（扫码枪模拟器） | Tabler **没有「连续扫码 + 逐条 ok/warn/bad 反馈」组件**（modal 本身用 Tabler 结构，反馈列表自写） | `styles/purchase.css` 的 `.pch-scan-*` + `scripts/purchase-shared.js` 的 `PchUI.openScan`，采购/库房 9 页复用同一组件 |
| 步骤条 / 状态灯 | Tabler **没有步骤条组件**；状态灯是原型专属语义件 | `styles/purchase.css` 的 `.pch-steps / .pch-light` |
| 库房统计条 / 效期徽标 / 备货双层布局 / 单位切换 | Tabler **没有统计条、效期三档徽标、药品明细⇄码清单双栏布局、单位切换开关** | `styles/wh.css`（`.wh-stats / .wh-exp-badge / .wh-pick-grid / .wh-unit-toggle`），文件头注释已注明「框架无此组件」 |

### 3.2 数据层（本轮关键取舍）

- **`scripts/drug-data.js`（PUL_DRUG）** — 药品字典主子表成为**唯一事实源**：主表 DRUGS（units 换算链 U3→U0、minUnit 拆零最小单位）+ 子表 IDCODES（7 位标识码 + 等级 + 包装规格）。`flat()` join 成老 `pch.dict` 形状，采购模块 20 处 `S.dict` 调用**零改动**透明切换。
- **`scripts/purchase-data.js`** — load() 时把 `s.pch.dict` 刷新为 `PUL_DRUG.flat()` 内存视图；`bad-codes.js` 维护写入改走 `PUL_DRUG.upsertFromFix`。
- **`scripts/wh-data.js`（PUL_WH）** — 库房在架库存**不加 status 字段**，用集合推导：在架 = 采购入库（已审核）+ 其他入库（已审核）+ 退回入库（已审核）− 采购退货（已审核）− 领用出库 − 其他出库（已审核）− 损耗（已审核）。在途 = pickDocs `status='已出库'` 单列。

### 3.3 核心机制验证（码⇄药转换）

`_t-wh-pick.html` 自动交互测试（`--virtual-time-budget=6000`）截图 `_shots/wh-pick-scan-r6.png`：

- 扫在架**箱码** `84147840007702017701`（2 级码，1 箱=60 瓶）→ 反馈「✓ 加罗新 **+60瓶**（已备 60/60）」——**换算链生效**，已备数按药品基本单位累计
- 扫非在架码 → 反馈「× 不在在架库存（未入库或已出库）」红拦截

## 四、怎么验证"真的用上了 Tabler"

1. **F12 看类名**：右键任意表格/按钮/卡片 → 检查 → class 里是 `table`、`card`、`btn btn-primary` 等 Tabler 类名。
2. **F12 Network 看加载**：刷新页面，能看到 `tabler.min.css`（约 693KB，本地文件）返回 200。
3. **抽掉即裸奔**：临时删掉页面 `<link ... tabler.min.css>` → 内容区立刻变成无样式的裸 HTML（侧栏不受影响，因为壳是自写的）。这是最有效的反向验证。

## 五、后续约束

- 新增页面：内容区组件**必须先查 Tabler 有没有**（https://tabler.io/docs 或本地 `shared/tabler/`），有才准自写；自写必须在对应 css 文件里注明"框架无此组件"。
- 若将来脱离 1440px 预览容器做全屏部署，壳可整体换回 Tabler 原生 `navbar-vertical`，届时折叠也直接用框架行为。

### 4.2 改造页面

- **登录页**：改为客户流程图四段式——账号 → 超管选院区/非超管自动进唯一院区 → 双栖用户先选「库房管理/药房管理」大卡 → 选具体库房/药房；唯一授权用户直达

## 十五、Round AA：退回入库单 → 领用退回 + 库房直收入口（2026-09-30）

起因：第一性原理重梳逆向领用退回——退回 = 两个物理事件（药房减/库房加），单据只是凭证；药房没建单但实物已退回时库房无入口。用户拍板口径：**退回码不一定在货架上，一定有追溯码；先建退回单，再填写/扫码收码**。

## 十六、Round AB：领用业务流重构——备货=出库单草稿态（2026-10-01）

起因：用户质疑「备货单哪里来的、一步式是啥」，并对照老系统六图（缺药领用单/缺药备货/领用出库/领用扫码）。第一性原理拆解：领用只有三个物理事件（要药/出库/收货），**备货不是独立单据，是出库单的草稿态**。老系统证据：一张单 4 状态（待提交→待备货→待出库→完成）、3 来源（缺药领用/领用扫码/采购入库）；老「备货」=数量确认不扫码，「领用出库」=扫码过账（两段制挑→核）。

用户拍板：**方案 A 统一状态机+双页分工；备货进度落盘（A2）；一体制**（扫码即备货、数量由码折合对差，不恢复两段制）；**库房主动制单纳入本轮**。设计稿 `docs/superpowers/specs/2026-10-01-pick-draft-unify-design.md`（V2），计划 `docs/superpowers/plans/2026-10-01-pick-draft-unify.md`。

| 改动 | 文件 | 说明 |
|------|------|------|
| 状态机统一 | `wh-data.js` | reqPool：`待提交(仅库房制单)→待备货→备货中→已完成` + `source` 字段（药房申请/库房制单，migrate 兜底）；pickDocs：`备货中(草稿)→已出库(在途·扣账)→药房已入库(闭环)`；seed 加待提交制单 + 备货中草稿演示数据 |
