## 1. 背景与目标

PUL-FMS（药品现场精细化管理系统）已交付 27 页原型（登录骨架、字典、采购、库房 4 大模块），但系统的核心机制——**「码⇄药⇄单位」转换层**——目前只以代码形式存在（`drug-data.js` 的 conv 引擎），没有任何图示。开发交接需要一套图纸把全业务链路讲清楚。

### 设计原则（已与用户拍板）

1. **场景驱动**：每张流程图回答「谁、在什么条件下、做什么、药品此刻以什么形态存在」——映射真实业务，不映射原型页面完成度；以第一性原理从用户角度分析场景需求
2. **转换层是心脏**：码⇄药⇄单位的表存储结构和节点转换单独两张图讲透
3. **灵活兜底**：凡是自动解析可能失败的节点，必须画出人工后台维护入口；药房「入槽」与「不入槽直接发」是两条并列合法路径
4. **后期段不回避**：未设计环节以「待决方案分支」画出供评审讨论——**2026-09-23 三条开放问题已拍板，图上分支保留但标注已定方案与不推荐原因（§4）**

## 3. 核心机制事实依据（已从代码核实）

```
20 位追溯码 = 7 位标识码(产品资源码) + 9 位序列号 + 4 位校验位
parseCode(): slice(0,7) 查 IDCODES 子表 → 命中=drugCode+level+packUnit；未命中=null→异常码
conv(): units 换算链 [{u:'箱',eq:60},{u:'瓶',eq:1}]，eq=折合链尾单位数，链尾=库存基本单位
minUnit {u:'片',per:7} = 拆零最小制剂单位
库存双口径：存储按「码」（逐码带批次/效期/库位）；申请/统计按「药」（基本单位）→ 双层表达
```

出处：`scripts/drug-data.js`、`scripts/purchase-data.js:122-127`、`scripts/wh-pick.js`、`scripts/wh-data.js`

### 3.1 单位落在哪张表（2026-09-23 拍板，勿再问「追溯码上有没有单位」）

**药定基本单位，码定包装层级，追溯码只是实例编号。** 追溯码 20 位上 **没有单位字段**。

| 概念 | 落在哪 | 字段 | 本例（阿莫西林） | 注意 |
|------|--------|------|------------------|------|
| 库存基本单位 | 药品主表 DRUGS | `baseUnit` = `units` 链尾（eq=1） | **盒** | 申请单数量、界面库存数字都用它 |
| 最小销售包装 | 标识码 IDCODES | `level=1` 那条的 `packUnit` | **盒** | 设计约定 **应当 = baseUnit** |
| 本码包装层级 | 标识码 IDCODES | `packUnit` + `level` | 箱=2 / 盒=1 | 扫到哪一级，这一码就代表那一层 |
| 追溯码实例 | TRACE_CODE | **无单位字段** | 20 位编号 | 前 7 位查标识码，再关联药品换算 |
| 拆零单位 | 药品主表 DRUGS | `minUnit` | 片，1 盒=7 片 | **不是**基本单位；片没有独立追溯码 |

约定：**1 个一级码 = 1 个基本单位** → 在架码行数 = 药的盒（瓶）数。入库扫箱/中包码必须按换算链展开成一级码，箱码只写在盒码 `code2`，自己不进在架。

实例页：`docs/diagrams/13-box-instance.html`；模拟数据：`docs/diagrams/12-box-code-instance.md`。

## 4. 已拍板决策（2026-09-23，按第一性原理 + 竞品推导）

### 4.0 合规锚点（所有决策的出发点）

医保发〔2025〕7 号（国家医保局 / 人社部 / 国家卫健委 / 国家药监局，2025-03-19）：

- **2025-07-01 起**全国定点医药机构销售药品**「先扫码、后结算」，无码医保不予支付**；采集执行情况纳入定点协议考核
- **2026-01-01 起**全量采集上传（含非医保定点、工伤医疗协议机构）
- **豁免范围**：中药饮片、中药配方颗粒、院内制剂、**必须拆零发放的药品**、零散注射针剂（含术中用药、急诊抢救）

→ 三条不可让渡的约束：**码必须扫**（否则收不到医保钱）、**药必须发得出**（患者等不起）、**账必须对得上**（码数/药数/钱数闭合）。
→ 判据：哪个方案在不破坏这三条的前提下，让一线（药师/护士）的额外动作最少。
→ **拆零设计（`splitQty`）是监管明文豁免的合法例外**，不是偷懒——评审时必须明说。

### 4.1 处方→码映射：定 **方案 b**（图 4 / 图 7 已更新标注）

**推导**：处方 = 意图（需求），码 = 实物（某批某效期某盒），二者**时序上分离**——开方那一刻没人知道调剂员半小时后拿到哪一盒。一句话：**锁到不能再晚，绑到不能再早**。

| 方案 | 机制 | 结论 |
|------|------|------|
| a. 开单即锁码 | 开方时按 FEFO 预分配码并锁定 | ❌ 备选。把意图过早固化为实物；开方到发药常隔数小时，期间退方/改方/停嘱/被其他窗口扫走，异常分支占大头 |
| **b. 锁药品级数量，调剂时绑码** | 处方只锁数量（baseUnit），调剂出库时才绑定具体码 | ✅ **已定**。锁的是业务语义（数量），绑的是实物动作（码） |
| c. 完全后绑定 | 出库扫码时才扣账 | ❌ 备选。开方到发药之间库存虚高，患者缴费后到窗口才发现没药 → 退费，把风险转嫁给患者 |

**竞品佐证**：SPD 院内物流（海遇 / 医惠 / 国药器械 SPD）扫码发生在**拣货·复核·发药**环节，非开单环节 → 等价 b；自动化药房（健麾 / 艾隆）码在**补药入库时**就与储药槽绑定 → 即「码预绑货位」，b + 预绑货位。

**落地四步**：

1. 开方 → 锁药品级数量（与 `REQ_ITEM` 同口径：药 + baseUnit 数量）
2. 调剂 → 系统按 **FEFO + 货位**给出具体码，药师扫该码（码预绑货位，消掉 b 唯一的边界风险「有药却扫不出码」）
3. 拆零 → 走 `DOC_CODE.splitQty` 记本单消耗（§4.0 政策豁免）
4. 退方/停嘱 → 只释放药品级锁，**不涉码**

### 4.2 药 ↔ 槽 ↔ 灯绑定：药 N:N 槽（主数据），灯 1:1 挂槽

**推导**：三者不是同一性质的东西，绑定必须挂在最稳定的抽象上。柜 = 物理资产（极稳定）；槽 = 位置（会调整）；灯 = **焊死的硬件，不可复制**（最不稳定）；药 = 品规（一直在变）。

**绑定模型**：

```
柜 1:N 槽 1:1 灯        ← 灯永远挂在槽上，不挂药上（灯是物理硬件，一槽一灯）
药 N:N 槽               ← 主数据映射表，带「主槽 / 备用槽」标志
麻精 / 高危药：强制 1 槽 1 药（对齐麻精柜双人双锁监管实践）
```

**为什么不允许「一药一槽」硬绑**：高频药一槽装不下日用量 → 卡死（破坏「药必须发得出」）；长尾药几百个槽空着 → 浪费。根因是**把「位置」误当成了「药品的属性」**——槽的本质就是货位，与已建好的 `DRUGS.warehouse` / `WH_LOCATION` 同性质。

**竞品佐证**：健麾信息（605186，门诊药房自动化市占第一 ~30%）储药槽↔药品为**可配置映射表**，支持一药多槽 + 溢出/备用槽；D-plus 补药模块扫药码 → 系统指槽 → 灯亮，**绑定动作发生在补药入库**。

**这也解释了 Round I 为什么说「后期再议」**：它不是架构问题，是主数据配置问题，本来就不该在前期定死。实现上只需给灯具字典（Round I 已建）扩一个 `slotCode` 字段，不改架构。

### 4.3 病区段形态：两段都做，患者级绑定放发药环节

**推导**：追溯的终点是「药到了谁身上」，但**扫码动作应发生在信息最全、动作最省的地方**。发药那一刻码已知、患者已知（处方/医嘱号），绑定成本最低；病区再逐码扫一遍是**同一信息的二次录入，不产生任何新信息**。

| 期 | 做什么 | 理由 |
|------|--------|------|
| **本期** | **病区签收**：按单扫码确认数量与码清单 | 责任交接点（药从药房到病区，丢了要能定责），成本极低 |
| **本期** | **患者级绑定放发药**：发药单已带处方/医嘱号，码随单绑 | 信息最全，病区零额外动作 |
| 后期可选 | 病区移动护理 PDA 扫腕带执行核对 | **是护理系统的事，不是 PUL-FMS 的事**，接口对接即可 |

**竞品佐证**（竞品不是二选一，是两段都做，分歧只在患者级绑定落在哪）：

| 实践 | 病区做什么 | 患者级绑在哪 |
|------|-----------|-------------|
| 陕西医保局 SPD 全流程追溯 | 护士站 PDA 扫码确认接收 | 发药环节 |
| 麻醉/精神药品闭环管理 | 两段：运送 PDA 交接 → 护士站扫码确认 → 护士 PDA 扫腕带执行 | 执行时（处方码 + 物流码双向追溯） |
| 药品全链路追溯系统 | 护士站扫码墩 / 高拍仪，或移动护理 PDA 住院采码 | 病区 |
| 海遇 SPD | 护士领用扫码关联计费 | 使用时扫码注入患者信息 |

### 4.4 战略定位（评审时一并说）

国内二三级医院自动发药机渗透率仅约 **20%**（美国 2014 年已达 97%），前五名厂商合计 81.9%。→ 客户大概率**已经买了或正要买**自动化设备。

> **PUL-FMS 做「管理精细化层」，槽/灯做可对接的主数据层，设备对接健麾、艾隆——不做设备。**
