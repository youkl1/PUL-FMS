## 1. 背景与第一性原理

### 1.1 三条硬约束（已拍板，不变）

码必须扫 / 药必须发得出 / 账必须对得上。**本次新增立场：冲突时「药必须发得出」优先，码的账事后补平，异常全程留痕。**

### 1.2 药→码绑定三时点

| 时点 | 机制 | 场景 | 现状 |
|------|------|------|------|
| T1 事前 | 在架批量赋码/预贴码 | 预设药柜顺序（FEFO+货位预指定码） | ✅ 方案 b 已含；批量赋码 PRD 已写 |
| T2 事中 | 调剂时扫码绑定 | ①边扫边拿 ②抓药扫码 ③病房摆药扫码 | ✅ disp/tray 已交付 |
| T3 事后 | 先发药，手动补绑 + 异常台账 | 住院无扫码条件、入库无码、扫码失败降级 | ❌ 本设计 |

**所有异常场景的本质 = T2 失败 → 降级 T3。**

### 1.3 两个「赋码」的分工

| 机制 | 适用 | 归属 |
|------|------|------|
| 无码药造码（院内码生成） | 药本身无码（供应商未赋码/院内制剂/饮片） | 既有赋码 PRD（4.1/4.2） |
| 有码未扫手动补绑（本设计） | 在架有码但发药时未扫（扫码失败/住院无扫码条件） | 本设计（T3） |

两机制在异常台账会师，合并进同一篇 `assign.md` PRD。

## 2. 已确认决策（2026-09-30）

1. **适用范围**：门诊扫码发药时留「手动补绑」兜底逻辑（扫码失败不卡流程，当下补绑，结算时已有码，不碰医保「先扫码后结算」红线）；住院摆药默认事后补绑。
2. **补绑规则**：药柜药品按预设药柜货位顺序+FEFO；非药柜药品按入库先后 FIFO（实物由人按先进先出拿取，账实天然不一致由盘点/异常提醒反向修补）。
3. **台账闭环**：日结制——当日班后处理异常台账，超 24h 未确认自动升级提醒院区管理员。
4. **手动优先**：T3 首版只做手动补绑（系统推荐、人工选定）；自动化补绑引擎列 Non-Goal，后续迭代再评估。
5. **推翻 Round R「只标注不补功能」拍板**：disp/tray 本次正式补人工补绑通道。

## 3. T3 手动补绑设计

### 3.1 触发与流转

- **门诊 disp**：扫码失败（扫不出/码不符/实物无码）→ 行内「手动补绑」入口 → 弹窗展示系统按规则推荐的码清单 → 人工勾选确认绑定 → 处方正常完成结算。绑定记录打核验标记 `verified=manual`（人工补绑）。
- **住院 tray**：摆药单完成后（药已发）→ 单上「补绑码」入口 → 同上人工确认。
- **混合绑定允许**：同一处方部分行扫码、部分行手动补绑，行级独立闭环。

### 3.2 选码推荐规则（系统推荐序，人工最终选定）

- **药柜药品**（有货位/槽位预设）：货位顺序 → FEFO 效期先出 → 同批按入库先后
- **非药柜药品**：入库先后 FIFO
- 库存数量账在方案 b 锁数量时已扣，T3 补绑只动「码的归属」，**不重复扣库存**。码账与实物账的最终校准器 = 盘点。

### 3.3 码状态机与核验维度

- 绑定记录新增 `verified` 三档：扫码核验 / 人工补绑 / 复核确认
- **码状态机不变**（已绑→已发药→已结算），异常不新建码状态，只加核验维度，避免状态机膨胀
- trace-q 追溯查询：来源标记扩展「手动补绑」+ 核验状态展示

## 4. 异常台账（新增页面）

- **菜单**：发药管理组下「赋码异常台账」（自主新增项，挂「新」chip，客户菜单无此项需报备）
- **字段**：异常类型（扫码失败/码不符/住院后置）、处方号/摆药单号、药品+批次、补绑码、补绑规则、操作人、时间、状态
- **状态机**：待补绑 → 待复核 → 已确认 / 已改绑 / 已关闭
- **记录产生时机**（台账同时是补绑待办清单）：住院摆药完成未补绑 → 自动生成「待补绑」记录，驱动日结前补绑；门诊扫码失败手动补绑完成 → 产生「待复核」记录
- **日结制**：当日班后复核；超 24h 未确认 → 升级提醒院区管理员
- **处理动作三选一**：确认（账实相符，verified→复核确认）/ 改绑（释放错绑码回架、绑定正确码）/ 关闭（药已退等无需补绑情形）

## 5. 逆向流程收口

| # | 场景 | 设计 |
|---|------|------|
| R3 | 退药发生在补绑前 | 异常台账记录直接「关闭」，码池不动 |
| R4 | 补绑后退药 | 走既有 rx-ret/tray-ret 解绑回架，台账记录关闭留痕 |
| R5 | 绑错批次/码 | 双通道：异常台账「改绑」+ 盘点差异改绑（inv 模块加动作） |
| R6 | HIS 撤销处方 | 分时点：未发药=释放锁定、已绑码解绑回架（码复用）；已发药=转退药流程。**spec §9 老开放问题就此收口** |
| R7 | 已结算后退药 | 医保冲正走既有结算通道，列 Non-Goal 不新增接口 |

## 8. Non-Goals

- 自动化补绑引擎（后续迭代，积累手动补绑数据后再评估命中率）
- 医保冲正接口（走既有结算通道）
- 病区 PDA 扫码（护理系统范畴）
- 省平台上传口径变更
- 码签打印机驱动层对接（沿用赋码 PRD 既有 Non-Goal）

## 9. 开放问题

1. 门诊手动补绑的码上传医保时是否带「未实物扫码核验」口径，待医保办确认。
2. 异常台账页为自主新增项，需向客户报备确认。
3. 盘点「改绑」动作与盘盈盘亏过账的交互细节，批次③盘点 PRD 写作时细化。
