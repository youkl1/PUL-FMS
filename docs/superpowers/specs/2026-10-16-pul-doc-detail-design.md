# PUL-FMS 单据明细共享组件设计

- 日期：2026-10-16
- 状态：设计已确认，待书面复核
- 目标：统一药品明细、码明细、异常码的前端实现，公共修改只维护一处

## 1. 背景与问题

当前多个页面分别实现 `drugPanel / drugsPanel / codePanel / codesPanel / badPanel` 及页签逻辑。采购到货单与统一扫码已经采用最新的药品 11 列、码 12 列口径，但采购退货、其他入库等页面仍保留旧列和旧操作，产生了典型的「改一处、漏一处」。

已确认的重复实现包括：

- [purchase-arrive.js](../../../prototypes/2026-09/pul-fms-base-v1/scripts/purchase-arrive.js)：到货明细三页签，作为采购基准页。
- [scan-hub-ui.js](../../../prototypes/2026-09/pul-fms-base-v1/scripts/scan-hub-ui.js)：统一扫码三页签，作为扫码作业基准页。
- [purchase-out.js](../../../prototypes/2026-09/pul-fms-base-v1/scripts/purchase-out.js)、[wh-other-in.js](../../../prototypes/2026-09/pul-fms-base-v1/scripts/wh-other-in.js) 等：各自复制表格、空态、计数和事件绑定。

## 2. 目标与硬约束

### 2.1 目标

1. 公共列、列名、列序、页签、计数格式、空态和公共操作只有一份实现。
2. 标准单据页复用完整明细组件；非三页签布局复用独立表格组件。
3. 页面专属字段和操作通过配置扩展，不再复制公共表格。
4. 所有适用页面同批收编，完成后不保留新旧两套明细实现。
5. 增加防回退验证，避免后续页面再次绕过共享组件。

### 2.2 采购到货与统一扫码的零逻辑变化红线

以下两页只做等价渲染迁移：

- 采购到货单：不得改变 `docBad`、`scanTotalNum`、`scannedBase`、下载、人工补录、审核及保存逻辑。
- 统一扫码：不得改变 `HUB.ctxOf`、`PUL_SCAN` 调用、数量换算、扫码草稿、提交、清空及审核逻辑。
- 两页的数据池、存储键、状态字段、数量口径、接口参数和事件处理函数均保持不变。
- 页面原有事件处理函数继续留在页面，共享组件只通过回调触发原函数。

## 3. 收编范围

### 3.1 纳入

- 正式单据页中，单据级的药品清单、码详情/码明细、异常码/无库存码明细。
- 使用三页签、双页签或上下/左右独立卡片布局的上述表格。
- 统一扫码及扫码规则演示工作台中的同类明细表。
- 已核实的代表页包括采购到货、采购退货、采购入库、其他入库、其他出库、领用备货、领用出库、领用入库、药房退回出库、统一扫码和扫码规则演示；代表清单不是豁免清单，实施时以本条范围规则全量盘点。

### 3.2 不纳入

- `quick-scan.html`、`ph-scan-in.html` 等仅负责跳转的兼容页，因为没有实际明细 UI。
- 跨单据异常码台账的筛选、分页和定位功能；它可与单内异常码共享基础单元格渲染，但不混用页面职责。
- 药品字典、库存查询、追溯查询等非单据明细上下文的业务查询表。
- 与三类明细无关的普通页签，继续使用 `PchUI.tabsHeader`。

## 4. 组件架构

新增 `scripts/doc-detail.js`，暴露 `window.PulDocDetail`。沿用项目现有原生 JavaScript「生成 HTML + 渲染后绑定事件」模式，不引入框架、构建步骤或外部依赖。

```js
PulDocDetail.renderTabs(model, options)
PulDocDetail.renderDrugs(model, options)
PulDocDetail.renderCodes(model, options)
PulDocDetail.renderBad(model, options)
PulDocDetail.bind(root, handlers)
```

### 4.1 职责边界

- `renderTabs`：输出标准明细卡、页签和当前页签内容。
- 三个 `render*`：分别输出药品表、码表、异常码表，可嵌入工作台或自定义布局。
- `bind`：统一处理页签与公共操作事件，再回调页面原处理函数。
- 页面适配层：把当前单据或 `hubDoc` 转为标准模型，并提供专属列、专属操作及保存回调。
- 共享组件不审核、不落账、不直接写 sessionStorage，不接管扫码草稿。

## 5. 标准数据契约

组件不直接绑定某一个数据池，接收标准化视图模型：

```js
model = {
  drugs: [],
  codes: [],
  bad: [],
  activeTab: 'drugs'
}
```

### 5.1 药品行

标准字段覆盖：药品编码、药品名称、药品规格、包装规格、生产厂家、批准文号、批次、生产日期、有效期、单价、数量、扫码总量、差异、单位、金额、库位，以及页面扩展所需字段。

### 5.2 码行

标准字段覆盖：追溯码、药名、码层级、父级码、生产批次、生产日期、有效期、扫码数量、单位、核对状态、标识码、发码机构，以及拆零、货位、预期货位等扩展字段。

### 5.3 异常码行

标准字段覆盖：追溯码、标识码、异常原因、登记时间和处理方式。异常判定仍由原数据层或页面现有函数完成，组件只消费判定结果。

### 5.4 适配原则

- 原始字段到标准字段的映射可以留在各页薄适配层。
- 公共字段的标题、格式化、空值显示和 HTML 结构不得留在适配层。
- 新增业务数据本身不存在时，允许先补数据层；除此之外，公共展示修改只改共享组件。

## 6. 渲染与扩展规则

### 6.1 公共列注册表

- 药品公共列以采购到货和统一扫码当前 11 列为基准。
- 码公共列以两页当前 12 列同序同名为基准。
- 异常码公共列集中登记序号、追溯码、标识码、异常原因、时间和操作。
- 页面通过 `columns` 选择公共列，通过 `extraColumns` 增加专属列；不能覆盖公共列的标题和单元格实现。

### 6.2 页签与计数

- 默认顺序为药品清单、码详情、异常码；双页签页面只声明实际使用的页签。
- 药品页签默认取药品行数，异常码页签取异常行数。
- 码页签提供具名计数模式：`rows` 表示码行数，`scanQty` 表示扫码折合量。
- 采购到货继续使用 `scanQty`，统一扫码继续使用 `rows`，数值口径不得因迁移改变。
- 页签 HTML、计数括号、异常红色强调由组件生成，页面不得自行拼接同类页签。

### 6.3 空态与区域插槽

- 页面只传药品、码、异常码空态文字，组件统一计算 `colspan` 和空态结构。
- `header/footer` 仅用于单据信息、进度条、审核条、草稿提示等区域内容。
- 不得通过插槽传入另一套药品表、码表或异常码表。

### 6.4 操作扩展

- 页面通过 `actions` 声明可用操作，如移除码、移除异常、编辑异常、维护字典、重新解析、编辑批次。
- 公共操作名称、按钮样式和事件名由组件统一。
- 拆零、货位选择等专属操作可作为扩展列或扩展动作保留。
- 所有动态文本默认经 `PchUI.esc` 转义；扩展渲染也必须使用同一转义入口。

## 7. 事件与数据流

1. 页面从现有数据层读取单据，不改变原读取方式。
2. 页面适配层生成标准 `model` 和 `options`。
3. 共享组件生成明细 HTML，页面按现有 `renderAll` 流程挂载。
4. `PulDocDetail.bind` 绑定页签和公共操作。
5. 用户操作回调页面原处理函数；原函数继续完成保存、重渲染、草稿提交或弹窗。
6. 数据变化后仍由原页面重新生成模型并渲染，组件不维护第二份业务状态。

## 8. 异常与错误处理

- 缺少 `drugs/codes/bad` 时按空数组处理，并展示对应空态。
- 未登记的公共列、未知计数模式、声明了操作但未提供回调时，抛出带组件名和配置键的明确错误，避免静默错列或按钮失效。
- 空值统一显示为公共占位符；页面不得各自实现另一套空值格式。
- 组件异常不得触发任何数据保存或审核动作。

## 9. 迁移策略

1. 先建立共享组件及独立测试，使用采购到货和统一扫码的固定样本固化当前行为。
2. 采购到货、统一扫码等价接入，先证明原数量、状态和事件行为不变。
3. 同批迁移其他适用单据页和工作台；公共部分对齐，专属字段与操作通过扩展点保留。
4. 每迁移一页即移除该页旧公共表格实现，不保留可切换的新旧双轨。
5. 所有适用页接入后增加防回退检查，并完成全量回归。

## 10. 验证与验收

### 10.1 自动化验证

- 组件测试覆盖：公共列顺序、两种码计数模式、异常计数、空态 `colspan`、扩展列、操作回调、HTML 转义及错误配置。
- 采购到货固定样本覆盖：拉取单、清单录入单、手动扫码单、下载失败、人工补录码和异常审核拦截。
- 统一扫码固定样本覆盖：逐码核对、拆零、上架货位、异常移除、草稿恢复、提交和审核。
- 执行受影响页现有测试，以及 `_t-invariants`、`_t-post-assign`、`_t-guide`、`_t-scan-hub`、`_t-scan-lab` 和菜单同步校验。
- 所有改动的 JavaScript 执行 `node --check`。

### 10.2 防回退验证

- 已收编页面必须引入并使用 `PulDocDetail`。
- 已收编页面不得再次定义本地公共药品表、码表、异常码表或拼接同类页签。
- 检查只针对收编清单，避免误伤字典、查询和特殊业务表。

### 10.3 验收标准

- 修改一个公共列定义后，所有使用该列的收编页面同步生效，无需逐页修改。
- 采购到货和统一扫码的数量、状态、草稿、保存、审核及操作结果与迁移前一致。
- 页面专属能力和现有数据口径不丢失。
- 所有自动化验证通过，受影响页面无浏览器脚本错误。

## 11. 非目标

- 不借本次重构调整审核规则、状态词、扫码解析、单位换算或数据表结构。
- 不统一跨单据异常台账与单内异常码的业务职责。
- 不引入 React、Vue、Web Components 或构建工具。
- 不把页面专属字段全部删除以追求表面一致；专属能力通过扩展点保留。
