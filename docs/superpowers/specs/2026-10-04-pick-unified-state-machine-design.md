## 二、统一状态机

### 2.1 状态（一维五态 + 作废终态）

| 状态 | 含义 | 账/码 |
|------|------|-------|
| 待提交 | 草稿，仅本侧可见；看**计划数量** | 不扣账、不占码 |
| 待出库 | 已提交；扫码备货是**单内动作**，码渐满、单据数量渐满 | 不扣账；扫码落盘刷新续作 |
| 已出库·待入库 | 审核出库通过四道闸 | **扣库房在架**，码在途 |
| 已入库·待上架 | 药房整单审核入库（货位选填仅提示） | 码进药房在架，未写货位 |
| 已上架 | 扫码上架写 phLoc（码级） | 终态，可发药可退回 |
| 已作废 | 待提交/待出库可作废或删除 | 终态，释放码，不进流水不扣账 |

### 2.2 入口与捷径（三入口）

- **入口 A 药房申请**：建草稿（待提交）→ 提交 → 待出库
- **入口 B 库房制单**：空单直入待出库（沿用现口径）
- **捷径 C 药房扫码直生**（本轮新增）：药房在「药品扫码上架」扫到无对应在途单的码 → 系统直生**已审核**领用单（表头+清单+码明细一次落齐），状态直落已上架，库房在架同扣；库房侧只读可见。扫到异常码（非本库房在架/冻结/解析失败）进异常码明细，直生被拦截并提示。

### 2.3 事件表（不占状态位）

| 事件 | 触发 | 守卫 |
|------|------|------|
| 提交申请 | 药房草稿行内「提交库房备货」 | — |
| 扫码备货 | 待出库单内扫码，按换算链折基本单位 | 失效码/非申请药品/过期停用/盘点冻结（出库四道闸前置） |
| 审核出库 | 库房 | 出库守卫四道闸；全码解析成功 |
| 审核入库 | 药房整单审核，上架货位非必填 | 盘点冻结拦截 |
| 扫码上架 | 药房逐码扫 | 仅本房在架码；已上架再扫=换货位；预期货位不一致提示 |
| 扫码直生 | 上架扫码无对应单 | 码须在本库房在架且非冻结 |
| 作废/删除 | 待提交删草稿、待出库作废 | 释放码 |

## 三、表结构（一套四表，全程复用）

| 表 | 字段 | 各阶段变化 |
|----|------|-----------|
| **领用单表头** | 单号 / 申请药房 / 供货库房 / 来源（药房申请·库房制单·扫码直生） / 状态（五态） / 上架货位（选填） / 创建·提交·出库·入库·上架五组操作人+时间戳 / 备注 | 只有 status 与时间戳在变，**全程不换表不换单号** |
| **药品清单明细** | 药品编码 / 名称规格 / 厂家 / 批准文号 / 计划数量（申请时填） / 单据数量（扫码折合渐满） / 基本单位 | 待提交看计划数量；待出库起单据数量渐满 |
| **追溯码明细** | 码 / 关联药品 / 扫码头（库房备货·药房上架·药房直生） / 扫码时间 / 解析结果 | 备货、上架、直生写同一张表 |
| **异常追溯码明细** | 码 / 异常类型（单外码·解析失败·冻结·非本库房在架） / 出现环节 | 各环节共用，是审核闸门的拦截依据 |

**旧名映射**（对业务方讲解用）：领用申请单 = 表头+清单（待提交）；领用备货单 = 同单（待出库，码渐满）；领用出库单 = 同单（已出库）；领用入库单 = 同单（已入库·待上架）。

**原型落点预告**（下一轮重构时）：`wh-data.js` 的 reqPool ⋈ pickDocs 两池合并为单一 `pickDocs`，申请单即领用单的待提交态；`source` 字段已有（药房申请/库房制单），补 `扫码直生` 枚举值。
