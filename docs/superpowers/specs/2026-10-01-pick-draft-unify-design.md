> 决策记录：方案 A（统一状态机 + 双页分工）+ A2（备货进度落盘），用户已拍板

## 一、背景与问题（第一性原理）

### 1.1 物理事实与单据的关系

库房→药房领用，物理世界只有三个事件，单据是事件的凭证：

| 事件 | 凭证 | 必然性 |
|------|------|--------|
| E1 药房要药 | 领用申请单（reqPool） | 可选（紧急/库房主动配货时无申请） |
| E2 药离开库房 | 领用出库单（pickDocs），扣账时点=审核出库 | 必有 |
| E3 药房收货 | 领用入库闭环（pickDocs.status=药房已入库） | 必有 |

**备货是 E2 之前的拣货作业环节，不是独立单据。**「备货单」本质是工作队列视图 = 待备货申请 + 备货中出库单草稿。

因果链：`申请(可选) → 备货作业(可选环节) → 审核出库(必然，诞生/推进出库单) → 药房入库(闭环)`

「一步式领用」跳过的是**申请单**和**两段式作业**（先备货后审核），不是跳过扫码；现文案「跳过备货」有误导。

### 1.2 现状四个问题

| # | 问题 | 位置 |
|---|------|------|
| P0 | **断链**：出库单页「+新增单据」生成 `备货中` 空 pickDoc →「✓审核出库」跳 `wh-pick.html?billNo=` → 被当只读 doc（kind='doc'），扫码备货按钮 disabled，永远走不通；且该行在备货单页操作列误显示「闭环」 | wh-pick.js L152-156、L414；wh-pick-out.js L113 |
| P1 | 无申请出库双入口冗余：备货单页「⚡一步式」（内存扫码即审）vs 出库单页「+新增单据」（落草稿续不上） | wh-pick.js btnQuick；wh-pick-out.js openNew |
| P2 | 状态口径两套：备货单侧 `待备货`(挂申请) vs 出库单侧 `备货中→待出库` 显示映射 | wh-pick-out.js L27 stText |
| P3 | 双页职责重叠：已出库/已入库单据两页都能看，一个按申请链、一个按出库单 | wh-pick.js rows() vs wh-pick-out.js list() |
| P4（新发现） | ledger-data.js 流水台账 pickDocs 循环**无状态过滤**，备货中草稿会被写成「领用出库」流水 | ledger-data.js L52-55 |

## 二、目标状态机（统一口径）

```
申请单 reqPool：   待备货 →（库房建草稿）→ 备货中（锁定）→（审核出库）→ 已完成
出库单 pickDocs：  备货中（草稿）→ 已出库（在途·扣账）→ 药房已入库（闭环）
```

- 一张申请 ↔ 至多一张出库单（1:1，沿用现状 docOfReq）
- 「备货中」是出库单的真实生命周期阶段，两页共用同一套词，不再做显示映射

## 三、概念模型：三个入口同构

所有备货作业都收敛为**「在一张备货中的出库单上扫码」**：

| 入口 | 动作 | 关联申请 |
|------|------|----------|
| 备货单页：申请行点「备货」 | 建草稿 `pickDoc{reqNo, status:备货中, codes:[]}`（已有草稿则复用），进工作台 | ✓ |
| 出库单页「+ 新增单据」 | 建空草稿（现状已有），**改为建完直接跳工作台** | ✗ |
| 备货单页「直接出库（无申请）」 | 弹窗选领用药房+备注 → 建空草稿 → 进工作台 | ✗ |

- 「⚡一步式领用（跳过备货）」**改名「直接出库（无申请）」**，消除"跳过备货"的误导
- 一步式与新增单据的区别只剩入口位置，产物相同（无申请空草稿）

## 四、页面分工

### 4.1 领用备货单 `wh-pick` = 工作台（看待办、干活）

- 列表行 = 申请链（申请⋈出库一行）+ 无申请草稿行，状态列四档：**待备货**（申请无草稿）/ **备货中** / **已出库·在途** / **药房已入库**，筛选项同步
- 行操作：待备货→「备货」；备货中→「继续备货」；已出库→「确认药房入库」（演示闭环保留）；已入库→「闭环」文案
- 选中备货中草稿 → 工作台模式：`doc.codes` 为唯一事实源（`picked={}` 内存态废弃），扫码/移除/清空实时写回 + save——**刷新不丢、换班可续**
- 深链 `?billNo=X`：备货中 → 工作台模式；已出库/已入库 → 只读（现状）
- 审核出库：草稿 status 推进为已出库（不再 unshift 新单），写 auditTime/operator/expectLoc，回写 req.status=已完成

### 4.2 领用出库单 `wh-pick-out` = 台账（看全部、管草稿）

- 全部 pickDocs（含备货中草稿），三页签只读明细不动
- 状态列去 stText 映射，直接显示「备货中/已出库/药房已入库」，筛选同步
- 备货中行操作：「继续备货 →」（跳 wh-pick?billNo=，现「✓审核出库」改名，审核动作只发生在工作台）+「✗ 作废」
- **作废规则放宽**：备货中草稿无论是否有码均可作废（未扣账、无库存副作用）；有关联申请时回写 req.status=待备货；现「有码请到备货单处理」拦截删除
- 「+ 新增单据」保存后直接跳工作台（替代现 toast 提示）

### 4.3 不动的页面

- 出库明细查询（wh-out-query）、入库明细查询（ph-in-query）、领用入库（ph-req-in）、药房库存（ph-stock）——均只见过账单据，天然兼容

## 五、联动与防重

| 场景 | 规则 |
|------|------|
| ph-req 申请侧 | 申请状态为**存储值**：wh-pick 建草稿时回写 `req.status='备货中'`，草稿作废回写 `'待备货'`，审核回写 `'已完成'`；ph-req 按 r.status 显示三档（待备货可编辑/撤销，备货中锁定文案「库房备货中」，已完成只读） |
| quick-scan 快捷扫码 | 选申请单时若已有备货中草稿 → 拦截「该申请正在备货中，请到领用备货单继续」；无草稿维持现状（审核时才建单直接已出库）。快捷页是一屏连续作业，无中途续作场景，不改成草稿制 |
| ledger-data.js L52 | pickDocs 循环加 `if (!W.pickPosted(d)) return;`——草稿不进流水台账 |
| 审核时再校验 | 草稿可能放了几天，码或被其他出库/损耗出掉：审核时对照 stockMap 重验，失效码列出并要求移除后再审（现状即时审核无此窗口，持久化后必须补） |

## 六、数据与种子

- pickDoc 字段不变（billNo/reqNo/date/pharmacy/warehouse/status/codes/operator/remark/auditTime），备货中草稿 auditTime 为空
- wh-data.js seed 加 1 条备货中草稿（含 2 个在架码、关联 1 条待备货申请→申请状态改备货中）供演示
- migrate 无需改（无状态假设）

## 七、边界与异常清单

| 边界 | 处理 |
|------|------|
| 空草稿审核 | 审核按钮 disabled（现状保留） |
| 超申请数扫码 | warn 提示不拦截（现状保留） |
| 非在架码/重复码/非本申请药品 | 拦截（现状保留） |
| 重复点「备货」 | 复用已有草稿，不重复建单 |
| 作废有码草稿 | 允许，confirm 提示「码未扣账，作废即释放」；有关联申请回写待备货 |
| 草稿期间码被其他单据出掉 | 审核时重验在架，失效码列出拦截 |
| 一步式无申请 | 不带上架货位（expectLoc 空，现状口径保留） |
| 库房冻结（nodeFrozen） | assertUnfrozen 拦截（现状保留） |

## 九、验证方式

1. `_t-invariants.node.js` 既有断言（备货中不扣账）继续通过
2. `_t-wh-pick.html` 自动交互测试更新后跑通（headless 截图）
3. 手动走查五条路径：申请→备货→审核→入库闭环；新增单据→工作台续作→审核；直接出库；作废有码草稿→申请恢复待备货；快捷扫码选已备货申请被拦截
4. 流水台账确认草稿不出现

## 十、Non-Goals

- 不改库存推导、在途口径、药房侧入库核对逻辑
- 不补写 pickOut PRD（specs 台账仍 🚧，本设计稿可作为其输入）
