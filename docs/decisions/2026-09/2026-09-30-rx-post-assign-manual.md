# 后置赋码（T3 手动补绑）——先把药发给病人，事后手动补绑追溯码

- **日期**：2026-09-30 拍板；2026-10-01 部署上线
- **状态**：已定稿，已交付并部署（http://youkailong.cn/pul-fms/）
- **设计稿**：`docs/superpowers/specs/2026-09-30-rx-post-assign-manual-design.md`
- **实施计划**：`docs/superpowers/plans/2026-09-30-rx-post-assign-manual.md`
- **PRD**：`specs/2026-09/pul-fms/05-rx/assign.md`（V1.0，无码造码 V0.2 + T3 合并）

## 背景

药房出药赋码存在 T2 事中扫码失败的异常场景：入库无码、拆零、住院病区无扫码条件。**第一性原理约束**：不能卡流程——即使前置药-码转换有问题，药也必须发得出，异常要记录、事后补。

## 三时点模型

| 时点 | 机制 | 状态 |
|---|---|---|
| T1 事前 | 批量赋码 / 预绑货位（方案 b 已含） | 已有 |
| T2 事中 | 调剂扫码绑码（disp/tray） | 已有 |
| T3 事后 | **手动补绑**（本次新增） | 本次交付 |

所有 T2 失败统一降级 T3：药先发出去，事后补绑。

## 五条已确认决策

1. **适用范围**：门诊扫药出库留补绑兜底（当下同步补绑，结算时已有码，**不碰医保「先扫码后结算」红线**）；住院摆药默认事后补绑。
2. **选码规则**：药柜药品 = 货位序 → FEFO → 入库先后；非药柜 = FIFO。系统与实物天然不一致，靠**盘点 + 异常提醒反向修补**。
3. **台账闭环**：日结制 + 超 24h 升级提醒院区管理员。
4. **手动优先**：先支持手动（系统推荐码清单 + 人工勾选确认），自动化补绑引擎列 Non-Goal。
5. **领用出库单**：追加 pickOut 页，对齐老系统截图（上单据列表 + 下码详情/药品清单/无库存码三页签）。

## 关键机制

- **核验维度不改码状态机**：码记录加 `bindType:'manual'` + `verified:'待复核'/'已复核'`，与扫码核验并存。
- **补绑不重复扣库存**：占用由 `occupiedRxCodes` 从单据 items[].codes 派生，「先 save 再查架」时序约定。
- **台账状态机**：待补绑 → 待复核 → 已确认 / 已改绑 / 已关闭；每码一条台账记录（会计等式：同 excNo 连绑 2 码净增 1 条）。
- **守卫**：bindManual 校验码与药品匹配 + 拆零码拦截 + excNo 状态守卫前移到 push 前防污染。

## 逆向流程收口（R3-R7）

- 补绑后退药：走既有退药流程解绑回架，台账记录关闭留痕。
- HIS 撤销分时点：未发药放锁解绑回架 / 已发药转退药。
- 绑错双通道：台账改绑 + 盘点差异提示（盘点审核遇补绑记录给「疑似错绑」红提示）。

## Non-Goals

自动化补绑引擎（后续迭代）、医保冲正接口、病区 PDA、省平台、打印驱动。

## 开放问题

1. 门诊补绑码上传医保是否带「未实物核验」口径（待医保办）。
2. 赋码异常台账为自主新增菜单，需向客户报备。
3. 补绑推荐规则与药柜物理顺序一致时账实命中率最高，残余差异由盘点校准（假设）。
